## C. SIM-ЯДРО

Детерминизм чист: randi/randf вне SimRNG нет, Time.* нет, обходы словарей сортированы либо порядко-независимы, тай-брейки на месте.

### C1. Критические баги

1. 🔴 **Отзыв/паника/утопление не освобождают резервацию — агент-зомби навсегда.** `agent_system.gd:707-719` (recall), `:206-225` (PANIC), `:156-177` (DROWNING) переводят состояние БЕЗ `w.jobs.release(a)`. После цикла агент IDLE с job_id≠-1: новую задачу взять не может (`can_take_job` требует −1), старую не возобновляет (механизма нет), задача вечно `taken_by`. Сценарий: Отзыв во время стройки очага → агент выключен из игры до конца забега, стройку никто не достроит. Один эпизод паники — тот же эффект. `test_reservation_invariant_holds` этого не ловит (связь двусторонне цела). Фикс: release в трёх точках (как уже делает `_check_auto_recall`).
2. 🔴 **Load в цикл шторма теряет «LOW −30%»** — `sim_world.gd:371-372`: `refresh_cycle_effects()` вызывается ДО `is_storm = crisis.is_active(...)` → восстановленный `phase_scale` затирается единицей. Автосейв на границе цикла = сейв 10-го цикла всегда со штормом; «Продолжить» на самом сложном цикле даёт LOW 150 с вместо 105, `restored.to_dict()` ≠ сейву. Фикс: поменять строки местами. `test_crises_survive_save` сохраняет на 4-м (VISIT) — шторм в round-trip не попадает.
3. 🔴 **Ремонт бесплатный + активирует недострой (эксплойт).** `building_system.gd:284-299`: damaged-ветка не списывает `repair_cost` (он только отображается), а `_on_became_active` зовётся без проверки `state`. Эксплойт: расставить ПЛАНЫ деревянных лестниц ниже +3 (материалы не возить) → шторм пометит damaged → агенты «починят» бесплатно → рабочие рёбра графа за 0 материалов. Фикс: списывать 50% стоимости через MaterialRequester; `_on_became_active` только при ACTIVE.

### C2. Баги

### C3. Риски

- **R1** Голодные едят из затопленного склада: `_generate_needs`/`_nearest_storage` не проверяют `_is_dry` — агент ныряет за едой на HIGH, мокнет, мечется через DROWNING.
- **R2** Лебёдка: «кромка площадки» не валидируется; `basket_cell` может указывать в пустоту → haul телепортирует груз на недостижимую клетку; `_go_to_cell` с невалидной клеткой молча оставляет IDLE с резервацией (та же дыра, что C1.1).
- **R3** Брошенное в УЖЕ стоящую воду бессмертно (смыв только по `_crossed_down`): жёсткий отзыв на HIGH роняет котомку под воду — «налог на жадность» обходится. Порча не тикает вне складов — сырую добычу можно хранить на земле вечно.
- **R4** Наземный стак сливается без лимита stack_size («стак 40 утиля» уносится одним слотом).
- **R5** Трудяга не ускоряет стройку: `int(round(1.1)) = 1` в `_do_work`.
- **R6** `cmd_pick_card` снимает паузу до проверки валидности карты. **R7** Два PLANNED-плана лестниц в одну колонку — второй достроится с edge_id=−1 (материалы в никуда). **R8** «Крадёт 1 случайный стак» фактически собирает count по всем стакам предмета. — **не подтверждено** (ремонт sim, проверено тестом): `take(sid, item, chosen["count"], false)` берёт РОВНО count выбранного стака; из скольких физических стаков он при этом набран — на количество не влияет. В складе 7+5+3 добычи кража уносит 7. Ошибку легко принять за подтверждённую по разнице склада: склад на −2 в ту же фазу накрывает водой (LOSE_HALF) и параллельно тикает порча, и «пропало всё» получается без всякой кражи. **R9** `saved_info().seed` теряет биты 64-битного сида (шеринг битого сида). **R10** static в production_system (ARCH-06). **R11** REST не прерывается на границе HIGH→EBB — агент может простоять пол-отлива.
