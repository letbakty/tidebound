# CONVENTIONS — правила для кодинг-агента (вставляется/читается перед КАЖДЫМ этапом)

Ты работаешь над игрой TIDEBOUND в Godot 4.7.x (stable) на GDScript. Прежде чем писать код:
1. Прочитай `docs/02-architecture.md` целиком (границы слоёв, контракты, структура папок).
2. Прочитай раздел(ы) `docs/00-functional-spec.md`, указанные в промпте этапа.
3. **Прочитай файл(ы) из строки «Ресерч» в шапке промпта.** Там уже проверены по докам 4.7 сигнатуры API, разобраны известные баги движка и лежат готовые решения — не выясняй это заново и не изобретай своё. Если в промпте указан «Готовый код» из `research/code/` — переноси его, а не пиши с нуля (это черновики под наши контракты, но они не компилировались: сверь имена полей с тем, что реально сделали прошлые этапы).
4. Работай ТОЛЬКО в рамках своего этапа. Раздел «Не делать» в промпте — жёсткая граница.
Пометка `⚠️ НЕ ПОДТВЕРЖДЕНО` в ресерче означает инженерную оценку, а не факт из документации — такое проверяй сам.

## Проверка окружения перед работой (30 секунд, экономит час)

⚠️ **Внутри `godot/` не должно лежать ни одной второй копии проекта.** Godot сканирует
все `.gd` под `res://`, и на двух файлах с одинаковым `class_name` валит проект целиком:
`Class "X" hides a global script class` и сотни ошибок парсера подряд — при полностью
исправном коде. Самый частый источник — распакованный ZIP с GitHub (папка вида
`tidebound-main/`) или клон репозитория, положенный внутрь папки проекта.

Проект — это `godot/project.godot`. Корень репозитория проектом **не** является:
в нём лежат `docs/`, `prompts/`, `research/`, и открывать надо не его.

Три команды перед началом любого этапа:

```bash
ls godot/ | grep -iE 'tidebound|-main|copy|backup|[0-9]$'      # второй копии быть не должно
grep -rh '^class_name ' --include='*.gd' godot | awk '{print $2}' | sort | uniq -d
grep -rh '^id = ' --include='*.tres' godot/data | sort | uniq -d
```

Вторая и третья обязаны выводить пусто. Дубль `class_name` роняет проект, дубль `id`
у дефа тише и хуже: `DB` индексирует по `id`, и один деф молча затирает другой.
Найденную лишнюю копию — вынести за пределы `godot/` либо положить внутрь неё пустой
файл `.gdignore` (такую папку Godot пропускает целиком).

## Жёсткие правила кода
- GDScript со **статической типизацией везде**: `var hp: int = 3`, `func foo(a: float) -> bool`, `Array[int]`, `Dictionary[String, int]`. Нетипизированная переменная = дефект.
- Godot 4.7 API. ЗАПРЕЩЁН синтаксис Godot 3.x / раннего 4.x. Частые галлюцинации и их правильные замены:
  `yield` → `await` · `export/onready/tool` → `@export/@onready/@tool` · `instance()` → `instantiate()` · `connect("sig", self, "m")` → `sig.connect(m)` · `emit_signal("x")` → `x.emit()` · `KinematicBody2D` → `CharacterBody2D` · `Position2D` → `Marker2D` · `AnimatedSprite` → `AnimatedSprite2D` · нода `Tween` → `create_tween()` · `OS.get_ticks_msec()` → `Time.get_ticks_msec()` · `rand_range` → `randf_range/randi_range` · `deg2rad` → `deg_to_rad` · `stepify` → `snapped` · `Pool*Array` → `Packed*Array` · `File/Directory` → `FileAccess/DirAccess` · `update()` → `queue_redraw()` · `.empty()` → `.is_empty()` · `remove()` → `remove_at()` · `world_to_map/map_to_world` → `local_to_map/map_to_local` (на TileMapLayer) · `setget` → `set:/get:` · нода `TileMap` → `TileMapLayer` (set_cell БЕЗ номера слоя: `layer.set_cell(coords, source_id, atlas)`).
- При наследовании: `_ready/_process` НЕ вызывают родительские неявно — нужен `super()`.
- В `res://sim/` ЗАПРЕЩЕНЫ: Node и всё нодовое, `get_tree()`, автолоады, `await`, `Timer`, физика, `Time.*`, `randi()/randf()` (только `SimRNG`), `print` (только `push_warning/push_error` в ошибках).
- UI не трогает sim: только `Game.cmd_*` вниз, сигналы `Events` вверх. View-ноды без игровой логики.
- Встроенный `TIME` в шейдерах ЗАПРЕЩЁН — только `global uniform float sim_time` (research/05): `TIME` не останавливается на паузе, и вода продолжала бы волноваться на тактической паузе. Исключение — UI-анимации, но они и не шейдерные.
- Все игровые числа — из `sim/balance.gd` (const) или `data/**/*.tres`. Магическое число в коде системы = дефект.
- Дефы (Resource) иммутабельны в рантайме. Изменяемое состояние — только в sim-классах.
- Строки UI — через `tr("KEY")`; ключи добавляй в `assets/i18n/strings.csv` (колонки: key,ru,en).
- Файлы snake_case, `class_name` PascalCase, ноды PascalCase, приватное `_prefix`, сигналы в прошедшем времени. Отступы — табы. Комментарии по-русски, только «почему».

## Обязательный финал каждого этапа
0. ⚠️ **`assert()` вырезается в release-сборках** — все проверки в тестах пиши через свой `check(cond, msg)` из `tests/test_ctx.gd`, иначе экспорт-сборка «пройдёт» все тесты молча.
0a. ⚠️ **Зелёные тесты не значат «работает».** В проекте уже был случай: 365 `SCRIPT ERROR` за прогон при полностью зелёном отчёте — материалы станций молча не списывались одиннадцать этапов подряд. **После прогона тестов посмотри в лог на `SCRIPT ERROR` и `push_error`,** даже если всё зелёное. Ноль ошибок — часть приёмки, а не бонус.
1. Добавь/обнови тест в `res://tests/test_<система>.gd` и подключи в `tests/run_all.gd`.
2. Прогони: `godot --headless -s res://tests/run_all.gd` — все тесты зелёные.
3. Запусти игру на 2–3 минуты (`godot --headless` смоук, если этап без UI; иначе обычный запуск) — нет ошибок в консоли.
4. Кратко перечисли в ответе: созданные/изменённые файлы, добавленные сигналы/константы, отклонения от промпта (если были — почему).

## Если что-то не сходится
- Конфликт промпта с docs/ — приоритет у docs/00 (правила игры) и docs/02 (архитектура); отметь конфликт в ответе.
- Не хватает данных — прими минимальное разумное решение, зафиксируй его комментарием `# РЕШЕНИЕ:` и в ответе. НЕ выдумывай новые системы.
- Нужен ассет, которого нет, — сделай программную заглушку (ColorRect/Placeholder-текстуру 32×32 с подписью), не блокируйся.
