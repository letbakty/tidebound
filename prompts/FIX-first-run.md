# Первый запуск из чистого клона

**Модель:** Sonnet 5 или Fable 5. Работа механическая и проверяемая: ни одного решения о правилах игры.
**Очередь:** можно **параллельно с чем угодно** — трогает файлы, которых не касается ни один другой промпт.
**Ты трогаешь:** `.gitattributes` (создать), `README.md` в корне (создать), `godot/README.md`, `godot/tools/doctor.gd` (создать), `godot/tests/test_project_integrity.gd` (создать), `godot/tests/run_all.gd`.
**Читать:** `prompts/CONVENTIONS.md` раздел «Проверка окружения перед работой»; `docs/02-architecture.md` §7 (про обязательный `--import --quit`); `docs/04-platform-checklist.md` §5.

⚠️ **В коде проекта ошибок нет — их искать не надо.** Дефект в другом: путь от `git clone` до запущенной игры **никто ни разу не прошёл**, и всё, что на нём лежит, обнаруживается только чужими граблями. Одни грабли уже собрали: на чужой машине проект встретил владельца 434 ошибками парсера и `Class "InputService" hides a global script class` — при полностью исправном коде.

## Блок 1 — семь shell-скриптов ломаются на Windows

`.gitattributes` в проекте **нет**, а в репозитории семь `.sh`:

```
godot/tools/audit_sim.sh   godot/tools/playtest.sh   godot/tools/remapcheck.sh
godot/tools/run_tests.sh   godot/tools/shoot.sh
research/code/audit_sim.sh research/code/make_gif.sh
```

Установщик Git для Windows по умолчанию ставит `core.autocrlf=true`. При клоне он подменит переводы строк на CRLF, и каждый скрипт умрёт на первой же строке: `bash: ...: /usr/bin/env bash^M: bad interpreter` или `$'\r': command not found`. Проект уже клонируют на Windows — это не гипотеза.

**Сделать:** `.gitattributes` в корне репозитория:

```gitattributes
* text=auto eol=lf
*.sh text eol=lf
*.gd text eol=lf
*.tres text eol=lf
*.tscn text eol=lf
*.md text eol=lf
*.csv text eol=lf
*.png binary
*.wav binary
*.ttf binary
```

⚠️ Файла мало: у тех, кто уже склонировал, рабочее дерево не поправится само. В README (блок 2) написать одну строку про `git add --renormalize .` — и то же самое проверяет доктор из блока 3.

## Блок 2 — репозиторий не говорит, как его открыть

**Корневого `README.md` нет вообще.** Посетитель GitHub видит пустую страницу и список папок. Именно так и получились те 434 ошибки: человек распаковал ZIP внутрь папки проекта, потому что нигде не написано, что проект — это `godot/project.godot`, а корень репозитория проектом не является.

**`godot/README.md` устарел на двадцать этапов:** «Выполнен **этап 00** (каркас). Следующий шаг — `01-sim-clock-and-bus.md`». Читающий решит, что перед ним пустой скелет.

**Сделать корневой `README.md`** — короткий, для человека, который видит проект впервые:

1. Что это за игра — три-четыре строки, без маркетинга.
2. **Как запустить**, по шагам и с командами: клонировать → открыть в Godot **4.7.2** именно `godot/project.godot` → первый запуск переимпортирует ассеты, это нормально и занимает минуту.
3. **Куда НЕ надо**: не открывать корень репозитория как проект; не распаковывать вторую копию внутрь `godot/` — Godot валит проект целиком на двух одинаковых `class_name`.
4. Как прогнать тесты и игру: `--import --quit`, затем раннер, затем `tools/playtest.sh`.
5. Что лежит в каждой папке — таблицей на семь строк.
6. **Чего в репозитории нет и почему:** `godot/.godot/` (кэш импорта, создаётся сам), `vendor/` (заголовки Steamworks SDK — лицензия Valve запрещает их распространять, скачиваются отдельно), `art-rd/` кроме `processed/`.

`godot/README.md` привести к правде: движок, рендерер, текущее состояние — этапы 00–20 закрыты, и ссылка на `STATE.md` как на источник правды.

## Блок 3 — доктор: пусть проект диагностирует себя сам

`godot/tools/doctor.gd`, запуск одной строкой без всякого shell (важно: на Windows его нет):

```bash
godot --headless --path godot -s res://tools/doctor.gd
```

Шесть проверок. У каждой — **что не так и что сделать**, по-русски, а не код ошибки:

| # | Проверка | Как чинить (это и печатать) |
|---|---|---|
| 1 | Вторая копия проекта внутри `res://` — папка с `project.godot` внутри или два одинаковых `class_name` | вынести за пределы `godot/` либо положить внутрь пустой `.gdignore` |
| 2 | Дубли `id` у дефов в `data/**/*.tres` | `DB` индексирует по `id`, второй деф молча затирает первый |
| 3 | Битые ссылки `res://` из `.gd`, `.tscn`, `.tres` | назвать файл и строку |
| 4 | Версия движка не `4.7.x` | назвать, какая нужна, и что проект пинится через `config/features` |
| 5 | CRLF в `tools/*.sh` | `git config core.autocrlf false`, затем `git add --renormalize .` |
| 6 | Импорт не выполнен (нет `.godot/`) | `godot --headless --path godot --import --quit` |

Выход: `0` — всё чисто, `1` — есть находки. Печатать итоговой строкой «проверок N, находок M», чтобы результат читался с одного взгляда.

⚠️ Проверка №1 обязана искать **и папку с вложенным `project.godot`, и просто дубль `class_name`**: вторая копия бывает и без файла проекта — например, если положили только `godot/`.

⚠️ Доктор в релизную сборку не идёт: `tools/` уже вырезан `exclude_filter` во всех пресетах. Ничего дополнительно делать не надо, но проверить, что так и осталось.

## Блок 4 — то же самое, но в прогоне тестов

`godot/tests/test_project_integrity.gd`, подключить в `tests/run_all.gd`. Три проверки из шести — те, что видны изнутри движка и не зависят от машины:

- дублей `class_name` нет;
- дублей `id` у дефов нет;
- все ссылки `res://` ведут в существующие файлы.

Смысл разделения: доктор ловит **сломанное окружение**, тест ловит **сломанный коммит**. Первое чинит человек, второе не должно доехать до `main`.

Логику не дублировать: общие функции держать в `doctor.gd` статическими и звать из теста. `tools/` вырезан только при экспорте, тесты живут в том же дереве и вызвать его могут.

## Приёмка

Автотестов тут мало, и главная проверка — единственная честная:

**Пройти путь новичка на настоящем чистом клоне.** Не в рабочей папке, а во временной:

```bash
git clone <репозиторий> /tmp/tb-clean && cd /tmp/tb-clean
```

Дальше ровно по шагам собственного README, ничего не додумывая:

1. `godot --headless --path godot -s res://tools/doctor.gd` — **находок ноль**;
2. `godot --headless --path godot --import --quit` — импорт проходит;
3. `godot --headless --path godot -s res://tests/run_all.gd` — зелено, **ноль `SCRIPT ERROR` в логе**;
4. `godot/tools/playtest.sh` — зелено;
5. открыть `godot/project.godot` в редакторе — **ноль ошибок парсера**.

Если на любом шаге что-то не сошлось — README неверен, и править надо README, а не обходить шаг руками.

Отдельно проверить, что доктор **находит** поломки, а не просто молчит: скопировать `godot/ui` в `godot/tmp-copy`, убедиться, что проверка №1 сработала и объяснила, что делать, и удалить копию. Проверка, которая никогда не срабатывала, — не проверка.

Временный клон после приёмки удалить.

## Не делать

Не трогать `sim/`, `game/`, `ui/`, `data/` — в коде ошибок нет, и искать их здесь не задача. Не заводить CI: для него нужен отдельный разговор и образ с Godot 4.7.2 (`docs/backlog.md`). Не добавлять зависимостей и аддонов. Не переписывать `.gitignore` сверх того, что требуется. Не чинить `vendor/` — его отсутствие в репозитории намеренное, про него нужна строка в README, и только.
