# Промпты для кодинг-агентов — TIDEBOUND

Папка содержит поэтапные промпты для сборки игры агентами (Claude Code). Каждый файл — один этап = одна сессия агента.

## Как пользоваться

1. Выполни этап 00 (создание проекта), дальше открывай Claude Code в папке `tidebound/` (корень, чтобы агент видел `docs/`, `prompts/` и `godot/`).
2. Начинай сессию сообщением вида:
   > Прочитай prompts/CONVENTIONS.md, файлы из строки «Ресерч» в шапке промпта и выполни этап из prompts/NN-….md
   Либо вставь содержимое промпта целиком — но CONVENTIONS и указанный ресерч агент обязан прочитать в любом случае.
   В `research/` лежит технический ресерч под каждый этап (API 4.7 выверен по докам, известные баги, готовые решения) и `research/code/` с черновиками кода к переносу. Карта «промпт → что читать» продублирована в [research/README.md](../research/README.md).
3. Один этап — одна сессия и один git-коммит. Перед коммитом агент обязан прогнать headless-тесты (это записано в CONVENTIONS).
4. Если агент предлагает изменить контракт (сигнал, структуру папок) — это допустимо только с одновременной правкой `docs/02-architecture.md`. Промпты дальше по цепочке опираются на контракты.
5. Новую фичу вне промпта не добавлять. Правило проекта: новая идея = обмен на что-то из плана, решает человек, не агент.

**Логика выбора модели** (эвристика, не бенчмарк): Opus 5 и Fable 5 — старшие модели, бери любую из них там, где этап архитектурный, многосистемный или требует держать в голове контракты (01, 05–07, 09, 11, 12, 19). Sonnet 5 — быстрее/дешевле и уверенно справляется там, где промпт сводится к точному переносу таблиц и спек (00, 03, 08, 10, 15–17). Пометка «Fable 5» на визуальных этапах (13, 14, 18) — рекомендация пробовать её первой на вёрстке и полировке; если результат не нравится — перезапусти этап на Opus 5. Haiku для этапов не рекомендую: цена ошибки в контрактах выше экономии.

**Параллелить можно:** ветку UI (12) — параллельно sim-этапам 04–11 (разные папки, общая точка — только Events/контракты). Больше двух параллельных сессий не советую: вырастут конфликты в git.

## Что где лежит

- `CONVENTIONS.md` — правила кода для КАЖДОЙ сессии (стиль, запреты, Godot 4.7-апи, финал этапа).
- `../research/` — технический ресерч по этапам + `research/code/` с готовым кодом. Ссылки на нужные файлы уже стоят в шапке каждого промпта.
- `FIX-review.md` — **ремонтный проход** по находкам из `../review/` (≈69 наблюдений по этапам 00–11). Не этап конвейера: запускать параллельно UI-ветке и обязательно до 17–19. Трогает только `sim/`, `data/`, `tests/`, `docs/`.

## Если этап провалился

Откатись к коммиту предыдущего этапа (`git reset --hard`), перезапусти сессию с той же инструкцией на старшей модели. Не проси агента «дочинить» наполовину сломанный этап в той же сессии дольше двух попыток — дешевле переделать с чистого состояния.
