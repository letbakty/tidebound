# Управление: ремап, геймпады и окно настроек

**Модель:** Opus 5 или Fable 5. Работа не объёмная, но контрактная: формат хранения переживёт все патчи игры, и переделать его потом = сбросить настройки всем игрокам.
**Очередь:** **после `FIX-mouse-and-panels.md`.** Тот правит `tools/playtest_run.gd` и `ui/screens/screen_base.gd`, от которого наследуется экран настроек. Параллелить с ним нельзя.
**Ты трогаешь:** `autoload/settings.gd`, `ui/screens/settings_screen.gd`, `ui/hud/button_hints.gd`, `tools/gen_input_map.gd`, `project.godot` (перегенерацией), `assets/i18n/strings.csv`, `game/camera_rig.gd`, `ui/hud/gamepad_cursor.gd`, `research/32-accessibility-remap.md`.
**Читать:** `docs/03-screens-spec.md` §3.6 (состав пяти вкладок — это спека, которую ты закрываешь); `research/32-accessibility-remap.md` §4 (ремап) — **в нём есть устаревший вывод, см. блок 5**; `research/20-input-gestures-gamepad.md` §6 (геймпад, Steam Deck, фокус-навигация); `research/10 §5` (почему `physical_keycode`).

⚠️ Всё ниже проверено запуском на Godot 4.7.2. Числа и строки — замеры, а не предположения.

Коротко: вкладка «Управление» выглядит готовой, но **ремап не переживает перезапуск, а переназначение клавиши стирает кнопку геймпада на том же действии.** Плюс все геймпад-привязки в проекте прибиты к устройству №0 — второй или переподключённый контроллер не работает вовсе.

## Блок 1 — ремап, который не сохраняется и портит соседние привязки

### 1.1 Сохранённый ремап не применяется никогда

`autoload/settings.gd:298` кладёт прочитанное в поле `bindings`, и на этом всё: **никто не вызывает `InputMap` при загрузке.** `apply()` (строка 121) трогает язык, окно, звук и тему — ввод не трогает.

Замер: переназначили «Отзыв» на `R`, сохранили, перечитали файл, вызвали `apply()` —

```
в файле лежит:            { "recall": ["R - Physical"] }
после загрузки настроек:  recall = Space - Physical | Joypad Button 1 (…)
```

**Фикс:** `Settings.apply_bindings()`, вызываемая из `_ready` после `load_settings()` и до первого кадра. Порядок обязателен: `capture_defaults()` должна снять умолчания **до** применения оверрайдов, иначе «Сбросить к умолчаниям» вернёт не умолчания, а оверрайд. Сейчас `capture_defaults()` живёт в `game/main.gd:71` — то есть уже после `Settings._ready`; перенеси в `Settings`.

### 1.2 Формат хранения нечитаем обратно в принципе

`settings.gd:224` пишет `bindings[action] = [event.as_text()]`. Проверено: **в Godot нет `from_text`** —

```
InputEventKey умеет from_text: false
```

И сама строка не годится ни для файла, ни для экрана:

| Что | `as_text()` |
|---|---|
| Пробел | `Space - Physical` |
| Кнопка B на геймпаде | `Joypad Button 1 (Right Action, Sony Circle, Xbox B, Nintendo A)` |

**Фикс:** хранить структуру, а не текст. Схема на каждое событие:

```gdscript
# клавиша:  {"type": "key",  "physical_keycode": int, "ctrl": bool, "shift": bool, "alt": bool, "meta": bool}
# кнопка:   {"type": "pad_button", "button_index": int}
# ось:      {"type": "pad_axis",   "axis": int, "axis_value": float}
```

`physical_keycode`, а не `keycode` — правило проекта из `research/10 §5`: иначе WASD на кириллической раскладке отдаёт «цфыв». Неизвестный `type` и неизвестное действие при чтении **молча пропускать**, а не ронять весь блок.

### 1.3 Переназначение клавиши стирает кнопку геймпада

`settings.gd:222` делает `action_erase_events()` и добавляет ОДНО событие. Замер:

```
до:                 recall = Space - Physical | Joypad Button 1 (…)
после ремапа на R:  recall = R - Physical
```

Кнопка геймпада исчезла. Та же беда со вторым набором клавиш: у `pan_left` привязаны `A` и `←`, и любой ремап убивает стрелку.

Это же и требование доступности: Game Accessibility Guidelines просят ремап **раздельно по устройствам ввода**, а не «одно действие — одна кнопка».

**Фикс:** у действия три слота, и правится ровно тот, который редактируют:

| Слот | Что принимает |
|---|---|
| Клавиатура, основная | `InputEventKey` |
| Клавиатура, запасная | `InputEventKey` |
| Геймпад | `InputEventJoypadButton` (и `InputEventJoypadMotion` для осей) |

В строке таблицы — три кнопки вместо одной сплошной. Захват принимает событие только того типа, чей слот редактируют: нажатие кнопки геймпада не должно попадать в клавиатурный слот и наоборот.

### 1.4 Подписи в интерфейсе нечитаемы

Сейчас на кнопку выводится `_action_keys()` — склейка `as_text()` через запятую. Скриншот вкладки: `Отзыв → «Space - Physical, Joypad Button 1 (Right Action, Sony Circle, Xbox B, Nintendo A)»` на всю ширину экрана.

**Фикс:**
- клавиши — `as_text_physical_keycode()`, он даёт чистое `Space` (проверено);
- кнопки геймпада — своя короткая таблица (`A`, `B`, `X`, `Y`, `LB`, `RB`, `Start`, `D-pad ←`), потому что `as_text()` у них длиной в 60 символов. Таблица уже наполовину есть в `ui/hud/button_hints.gd:HINTS` — вынеси её в одно место и пользуйся из обоих.

### 1.5 Подпись вкладки врёт

`SET_INPUT_NOTE` (строка 441 в `strings.csv`) гласит: «Схема управления и ремап клавиш **появятся здесь**; пока — текущие назначения». При этом кнопки нажимаются и ремап реально происходит — просто ломает соседние привязки и не сохраняется. Худший из вариантов: игрок думает, что смотрит справку, а правит настройки. Переписать строку под то, что вкладка делает после этого промпта.

## Блок 2 — геймпады

### 2.1 Работает только контроллер №0

`tools/gen_input_map.gd:96` создаёт `InputEventJoypadButton.new()` и не трогает `device`. Умолчание — `0`, а `InputMap` сравнивает устройство точно. Замер:

```
device по умолчанию: Key=16  JoypadButton=0  JoypadMotion=0  MouseButton=32
геймпад 0, кнопка B -> recall: true
геймпад 1, кнопка B -> recall: false
```

Игрок с двумя контроллерами, с подключённым рулём или просто переподключивший геймпад получает индекс 1 — и игра перестаёт видеть геймпад целиком.

**Фикс:** `device = -1` на всех событиях геймпада, и в генераторе, и в том, что создаёт ремап. Проверено — чинит:

```
геймпад 0 -> recall: true   геймпад 1 -> recall: true
геймпад 2 -> recall: true   геймпад 7 -> recall: true
```

После правки **перегенерировать карту**: `godot --headless -s res://tools/gen_input_map.gd`, и `project.godot` попадает в коммит.

⚠️ `-1` для клавиатуры и мыши **не ставить**: в 4.7 у них свои пространства (`DEVICE_ID_KEYBOARD = 16`, `DEVICE_ID_MOUSE = 32`, замерено), а `-1` там совпадает с `DEVICE_ID_EMULATION` и означает «эмулированное событие». Проект уже пользуется эмуляцией тача из мыши — не столкни их.

### 2.2 Подключение и отключение на ходу

Ничего не подписано на `Input.joy_connection_changed`. Игрок, подключивший геймпад при открытом окне настроек, не увидит ни строки.

**Сделать:** во вкладке «Управление», сверху — список подключённых устройств: `Input.get_connected_joypads()` + `Input.get_joy_name(device)`, обновляется по сигналу. Пусто — честная строка «геймпад не найден», а не пустое место. Godot 4.7 отдаёт ещё и `Input.get_joy_info()` (проверено, метод есть) — если там окажется имя производителя, покажи его, но не строй на этом логику.

Если кнопки контроллера определяются неправильно — это база SDL, а не наш код. Запиши в подсказку вкладки или в `docs/backlog.md` переменную `SDL_GAMECONTROLLERCONFIG` для тестеров: ей чинят экзотические геймпады без правок игры.

### 2.3 Подсказки кнопок врут после ремапа

`ui/hud/button_hints.gd:8–14` хранит подписи **константами** (`HUD_KEY_SPACE`, `HUD_PAD_B`). После ремапа полоса подсказок внизу экрана продолжает показывать старые клавиши.

Это ровно то, о чём предупреждал `research/32 §4.1` («три строки сейчас против переписывания всех подсказок потом») — и чего не сделали. Плюс у Steam Deck Verified прямое требование: экранные глифы обязаны соответствовать активному устройству ввода.

**Фикс:** `ButtonHints` берёт подпись из `InputMap` через тот же общий хелпер, что и вкладка настроек, и перестраивается по сигналу `Settings.bindings_changed`.

Заодно: русская строка `HUD_KEY_B` переведена как `B` кириллицей — на экране это читается как «В». Физическая клавиша латинская; подписи клавиш вообще не переводятся.

## Блок 3 — чего вкладка «Управление» не закрывает по спеке

`docs/03 §3.6` требует от вкладки четыре пункта. Сделан один.

| Пункт спеки | Сейчас |
|---|---|
| ремап клавиш списком с конфликт-подсветкой | есть (с дефектами блока 1) |
| **схема (мышь / геймпад / тач)** | нет |
| **чувствительность камеры** | нет |
| кнопка «сбросить к умолчаниям» | есть |

**Схема ввода.** Сейчас активное устройство определяется автоматически по последнему событию (`InputService._track_device`) — это правильное поведение и ломать его не надо. Пункт настройки нужен как **закрепление**: «авто / мышь / геймпад / тач», где не-авто запрещает переключение. Причина не косметическая: на Steam Deck подключённая клавиатура заставляет подсказки прыгать между раскладками.

**Чувствительность камеры.** Множитель к трём константам, которые сейчас зашиты:

| Константа | Где | Что делает |
|---|---|---|
| `PAN_SPEED_PX = 220.0` | `game/camera_rig.gd:21` | панорама с клавиш и стика |
| `DRAG_GAIN = 1.0` | `game/camera_rig.gd:23` | панорама драгом мыши и пальцем |
| `SPEED_PX = 720.0` | `ui/hud/gamepad_cursor.gd:11` | скорость виртуального курсора |

Один ползунок 50–200% на все три (значения — из `Settings`, не из констант) плюс отдельный ползунок мёртвой зоны стика (`gamepad_cursor.gd:12`, `DEAD_ZONE = 0.2`): у изношенных контроллеров дрейф стика делает курсор неуправляемым, и это самая частая жалоба на виртуальные курсоры.

## Блок 4 — что добавить сверх спеки

Это не «хотелось бы»: каждый пункт закрывает уже существующую дыру.

1. **Пресеты раскладок + «своя».** Guidelines просят профили вместе с полной свободой. Хватит трёх: «по умолчанию», «стрелки» (панорама на стрелках, действия на левой руке), «одна рука». Пресет — это тот же словарь оверрайдов, дополнительного кода почти нет.
2. **Сброс одной строки**, а не только всех сразу. Сейчас единственная кнопка сбрасывает весь список.
3. **Защита от неуправляемой игры.** Действие нельзя оставить совсем пустым; `Esc`/`ui_cancel` нельзя занять под игровое действие. Иначе игрок запирает себя без выхода в меню — Godot-сообщество называет это первой ошибкой любого ремапа.
4. **Конфликты считать против ВСЕХ действий, а не только переназначаемых.** `settings.gd:242` обходит только `REMAPPABLE`, поэтому повесить действие на `F1` (дебаг) или на `ui_accept` можно молча.
5. **Список `REMAPPABLE` неполон.** В нём нет оверлеев `overlay_marks` / `overlay_flood` / `overlay_jobs` (F2–F4) и нет `cursor_tap`. Guidelines требуют «all game controls»; F1 и режим съёмки — служебные, их не трогай.
6. **Вибрация на ПК.** Строка `SET_HAPTICS` показывается только при `OS.has_feature("mobile")` (`settings_screen.gd:196`), хотя вибрация геймпада есть и на десктопе. Godot-доки прямо просят давать ползунок отключения: «vibration can be uncomfortable for certain players». Показывать строку, когда подключён геймпад.
7. **Не поднимай `Settings.VERSION`.** `load_settings()` при несовпадении версии **выбрасывает весь файл** и берёт умолчания (`settings.gd:310`) — то есть у каждого игрока слетят и звук, и язык, и доступность. Новые поля читаются через `d.get(key, умолчание)` и версии не требуют. Если версию всё же придётся поднять — писать миграцию, а не сброс.

## Блок 5 — решение, которое надо пересмотреть

`research/32 §4.2` заканчивается выводом: **«Для Steam-версии свой ремап геймпада не нужен вовсе»** — мол, игрок переназначит кнопки в оверлее Steam Input.

Этот вывод больше не годится, и вот почему:

- Game Accessibility Guidelines формулируют прямо: системный ремап — «страховка, а не замена ремапу внутри игры». Причины называются те же, что у нас болят: подсказки в игре должны отражать текущую раскладку, а настройки должны лежать там, где игрок их ищет.
- Steam Input не покрывает сборки вне Steam. У проекта в планах веб-экспорт и itch (`research/31`) и мобильная сборка — там оверлея нет.
- Steam Deck Verified требует, чтобы **дефолтная** конфигурация давала доступ ко всему контенту без правки настроек. Это требование к раскладке по умолчанию, а не разрешение не делать ремап.

**Задача:** сделать ремап геймпада наравне с клавиатурным (блок 1.3 это и так предполагает) и **исправить сам вывод в `research/32 §4.2`**, чтобы следующий агент не принял старое решение за действующее. Правило проекта: расхождение промпта с документом — приоритет у документа, поэтому документ должен быть верным.

## Приёмка

- `godot --headless -s res://tests/run_all.gd` — зелено, **ноль `SCRIPT ERROR` в логе**.
- `tools/playtest.sh` — зелено.
- Новый тест `tests/test_input_bindings.gd`, подключённый в `run_all.gd`:
  - круг «событие → словарь → событие» для всех трёх типов, включая модификаторы;
  - ремап клавиши **не стирает** кнопку геймпада на том же действии;
  - `to_dict()` → `from_dict()` → `apply_bindings()` возвращает ровно то, что назначили;
  - `InputMap.event_is_action()` истинно для геймпадов с индексами 0, 1 и 2;
  - неизвестное действие и неизвестный `type` в файле не роняют загрузку;
  - конфликт ловится и против непереназначаемых действий.
- Руками: назначить «Отзыв» на `R`, **перезапустить игру**, убедиться, что `R` работает, кнопка геймпада на «Отзыве» жива, а полоса подсказок внизу показывает `R`, а не `Space`.
- Руками: открыть настройки, подключить геймпад — список устройств обновился без перезахода во вкладку.

## Не делать

Не трогать `sim/`, `data/` и баланс. Не менять сам набор действий и раскладку по умолчанию из `docs/00 §13` — она не сломана, чинится способ её менять. Не переносить служебные действия (`ui_*`, `debug_panel`, `capture_*`) в переназначаемые: их ремап ломает навигацию геймпадом, а это прямой отказ в Steam Deck Verified. Не писать интеграцию со Steam Input — это отдельный этап `20-steam-release.md`. Ни одной новой настройки сверх списка выше: новая идея меняется местами с запланированной, и решает это человек.
