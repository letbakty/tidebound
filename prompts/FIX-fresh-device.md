## Блок 1 — четыре депозита из восьми рисуются пурпурным

Настоящий баг, видно на первом же кадре чистого клона.

`game/world.gd:21` знает четыре вида:

```gdscript
const DEPOSIT_COLORS: Dictionary = {
	"ruins_near": Color("8a8f7a"), "ruins_deep": Color("6f7f8a"),
	"shallow": Color("c9a26b"), "kelp": Color("4f7a4a"),
}
```

А в `sim/balance.gd` их теперь **восемь**: волна контента добавила `brine_pool`, `fresh_seep`, `bone_shoal`, `shipwreck`. Строка 255:

```gdscript
rect.color = DEPOSIT_COLORS.get(kind, Color.MAGENTA)
```

Замерено пипеткой на кадре: `#EE13E6`. Половина новых депозитов светится ядовито-розовым посреди приливной отмели.

**Сделать:** четыре цвета в палитре игры (`art/tidebound.gpl`, холодные внизу — тёплые наверху, `docs/01 §4`). Соль на −1…−2 — светлая и сухая; пресная линза — холодная голубая; костяная отмель — бледная кость; обломки судна — тёмное дерево с ржавчиной.

⚠️ И то же самое рядом: `game/building_view.gd:20` `COLORS` не знает `weir`, поэтому верша рисуется серым `#909090` вместо своего цвета. Спрайта у неё нет намеренно (`gen_building_art.gd` `NO_ART`), а вот цвет заглушки должен быть свой.

**Чтобы это не повторилось** — проверка в `tests/test_project_integrity.gd` (он уже есть):

- у каждого ключа `Balance.DEPOSIT_KINDS` есть цвет в `WorldView.DEPOSIT_COLORS`;
- у каждого `special` из `data/buildings/*.tres` есть цвет в `BuildingView.COLORS`.

Обе — по три строки, и обе ловят ровно тот класс ошибки, который случился: систему расширили данными, а презентация об этом не узнала.

## Блок 2 — на Windows нечем пользоваться

В репозитории **семь `.sh` и ноль `.bat`/`.ps1`**. Человек на Windows без git-bash не может запустить ни доктора, ни тесты, ни `playtest.sh` — то есть ровно те команды, на которые его отправляет README.

Игра при этом на Windows работает: `.sh` нужны только для инструментов.

**Сделать минимум, который закрывает вопрос:**

`godot/tools/doctor.bat` — обёртка в две строки, которую можно запустить **двойным щелчком**:

```bat
@echo off
set GODOT=%GODOT%
if "%GODOT%"=="" set GODOT=godot
"%GODOT%" --headless --path "%~dp0.." -s res://tools/doctor.gd
pause
```

`pause` обязателен: без него окно закроется раньше, чем человек прочитает отчёт.

Так же — `run_tests.bat` и `playtest.bat` рядом с их `.sh`-близнецами. Логику не дублировать: `.bat` только зовёт Godot, вся работа остаётся в `.gd`.

В README — строка «на Windows: `tools\doctor.bat`, двойной щелчок».

⚠️ `.bat` обязаны быть с CRLF — это единственный формат, который понимает `cmd.exe`. В `.gitattributes` добавить `*.bat text eol=crlf`, иначе правило `* text=auto eol=lf` их сломает.

## Блок 3 — доктор пугает раньше, чем помогает

На чистом клоне **до импорта** первая команда README печатает три красные строки движка, и только потом свой отчёт:

```
SCRIPT ERROR: Parse Error: Identifier "SimTypes" not declared in the current scope.
   at: GDScript::reload (res://autoload/audio_service.gd:486)
ERROR: Failed to load script "res://autoload/audio_service.gd" with error "Parse error".
ERROR: Failed to instantiate an autoload, script 'res://autoload/audio_service.gd' does not inherit from 'Node'.
```

Причина понятна и безобидна: без `.godot/` нет кэша глобальных классов, поэтому автолоады не парсятся. Но человек, которому сказали «начни с доктора», видит три ERROR и делает вывод, что проект сломан. Диагностический инструмент обязан быть тише пациента.

**Сделать:** доктор печатает свою шапку **первой строкой**, до всего остального, и в разделе про импорт объясняет, что ошибки автолоадов выше — следствие несобранного кэша и уйдут после шага 2. Если автолоады можно не поднимать вовсе (`-s` с `--no-window` и пустой сценой) — тем лучше, но не ломай ради этого запуск.

## Блок 5 — про архив, из-за которого всё началось

Оба случая с 434 ошибками (`InputService`, потом `WaterView`) — это распакованный внутрь `godot/` архив «Download ZIP» с GitHub, папка `tidebound-main/`. Предотвратить это репозиторием нельзя: движок валится на дублях `class_name` раньше, чем выполнится хоть одна наша строка.

Что **можно** — сделать так, чтобы человек туда не пошёл:

- в README, в самом верху раздела «Как запустить», одной фразой: **клонировать, а не скачивать ZIP**, и почему (архив разворачивается в папку `tidebound-main/`, и если положить её рядом с проектом — движок увидит два комплекта скриптов);
- проверка №1 доктора уже это ловит — убедиться, что она срабатывает не только на вложенный `project.godot`, но и на **папку с дублирующимися `class_name` без файла проекта** (архив разворачивается именно так, если распаковать только `godot/`).

## Приёмка

Автотесты — обычные: `run_all.gd` зелено, ноль `SCRIPT ERROR`, `playtest.sh` зелено.

Дальше — то, ради чего промпт:

1. **Чистый клон и весь путь заново**, во временной папке, из локального репозитория после своего коммита. Пять шагов README, ни одного отклонения. Кадр игры снять и посмотреть глазами: **пурпурных квадратов на карте нет**.
2. **Смоделировать ошибку брата:** скопировать `godot/ui` в `godot/tidebound-main`, запустить доктора, убедиться, что находка есть и текст объясняет, что делать. Копию удалить.
3. **Проверить `.bat` на Windows-переводах строк:** `file godot/tools/doctor.bat` должен показать `CRLF`.
4. Новые проверки целостности **срабатывают**: временно убрать один цвет из `DEPOSIT_COLORS`, убедиться, что тест покраснел, вернуть.

Проверка, которая ни разу не падала, — не проверка.
