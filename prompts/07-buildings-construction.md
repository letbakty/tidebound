# Этап 07 — Постройки: размещение, стройка, износ, затопление

**Модель:** Opus 5 или Fable 5.
**Зависит от:** 06. **Читать:** docs/00 §8; docs/02 §5.
**Результат:** все 17 построек как данные; призрак размещения; агенты строят; затопление/поломка/ремонт/снос работают.
**Ресерч:** [research/17-buildings-production.md](../research/17-buildings-production.md) — три состояния + два флага, сетка занятости, призрак, лестницы и граф, **дедупликация HAUL**, шторм и hp, снос. Дополнительно: [research/14](../research/14-data-resources-tres.md) (генерация дефов), [research/16](../research/16-jobs-utility-ai-reservation.md) §9.

## Задача
1. `data/defs/building_def.gd` — `class_name BuildingDef extends Resource`: id, display_key, size: Vector2i, cost: Dictionary[String,int], min_mark/max_mark: int, flood_rule (SimTypes.FloodRule: OK/DISABLED), storm_breaks: bool, hp: int (дефолт 1), special: String (маркер логики: "ladder","storage","hearth","lantern","sluice","dryer","evaporator","winch","bunk","raincatcher","forge","workbench","saltery","ropery",""), storm_always: bool (только dryer: срывается штормом на ЛЮБОЙ отметке), unlock_id: String ("" = доступна сразу).
2. `data/buildings/*.tres` — все 17 из таблицы docs/00 §8 (id дословно). 🔒-постройки — с unlock_id.
3. `sim/building_system.gd` — `class_name BuildingSystem`:
   - Состояния: `PLANNED` (призрак, ждёт материалов) → `UNDER_CONSTRUCTION` → `ACTIVE`; отдельно флаги `flooded`, `damaged`.
   - `can_place(def_id, cell) -> bool`: проверка отметки (min/max_mark), пересечений, опоры (площадка под всей шириной), разблокировки (запрос к RunState.unlocks — интерфейс, наполнит этап 11; пока все "" доступны).
   - Размещение (`Game.cmd_place_building`): PLANNED, JobSystem создаёт HAUL-задачи «принести cost на место» и BUILD-задачу (5 с × единица стоимости суммарно). ⚠️ **Дублирование HAUL-задач — главная ошибка этого этапа** ([research/17](../research/17-buildings-production.md) §6): без учёта уже заказанного пять агентов понесут пять комплектов материалов на одну постройку. Заводи `MaterialRequester` (учёт «сколько уже в пути») — он пригодится трижды: стройка, топливо очага/фонаря, входы станций.
   - `can_place` — через **сетку занятости**, а не перебор всех построек ([research/17](../research/17-buildings-production.md) §2).
   - Затопление: пересечение уровня воды с отметкой → flood_rule: DISABLED → не работает пока в воде; спец-правила: evaporator теряет накопленную соль; hearth гаснет; lantern и sluice и лестницы работают.
   - Шторм (систему добавит этап 09; сделай метод `on_storm()` и вызов из SimWorld при событии): все с storm_breaks и mark < +3 → damaged; все со storm_always (dryer) — разрушаются в ноль с возвратом 0 на любой отметке; hp-логика: storage переживает 2 шторма (hp 2 → декремент).
   - Ремонт: REPAIR-задача, 50% cost, приносится и чинится как стройка.
   - Снос (`cmd_demolish`): мгновенно, 50% материалов (окр. вниз) на землю рядом.
   - Лестницы: при ACTIVE регистрируют ребро в Terrain (`add_ladder`), при поломке/сносе — убирают. Помост: расширяет площадку в Terrain.
   - Очаг/фонарь: расход топлива (1 сухой driftwood/цикл; фонарь — /2 цикла) — забирают со складов через HAUL-задачу «заправка» при остатке 0; без топлива — неактивны.
4. **Стартовые постройки** (docs/00 §11.1): при new_run размещать в состоянии ACTIVE: Очаг и Дождесборник на жилых ярусах у точки спавна (клетки — из CliffDef, добавь поле start_buildings). Подключи очаги к `SimWorld.heat_sources()` (замени заглушку этапа 05: источники тепла = работающие незатопленные очаги; TODO-07 из этапа 05 закрой). Радиус тепла: Balance.HEAT_RADIUS (=4; с разблокировкой u_hearth_big — 6, проверка по SimWorld.unlocked — список появится этапом 11, пока поле-заглушка `unlocked: Array[String]`).
5. Порядок тика: BuildingSystem встаёт в SimWorld.tick() между crisis и production (docs/02 §4 — порядок фиксирован).
6. Презентация: `game/building_view.tscn/gd` — заглушка: цветной прямоугольник size×32 с буквой, полупрозрачный для PLANNED, прогресс-бар стройки, мигание damaged, синий оттенок flooded.
7. Призрак размещения: `game/build_ghost.gd` — следует за курсором/пальцем (через world.screen_to_world), зелёный/красный по can_place. Управление призраком — из дебаг-панели (кнопки построек) до этапа 14.
