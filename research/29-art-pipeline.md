# 29 — Арт-пайплайн: Aseprite → Godot, палитра, атласы, анимация

**Для этапов:** 02 (тайлсет), 05 (спрайт агента), 07 (постройки), 09 (существа), 12/18 (UI-атлас), 18 (замена всех заглушек на финал).
**Дата ресерча:** 2026-08-21. **Движок:** Godot 4.7.x stable.

**Почему это Группа 1.** Заглушки этапов 02–09 задают **размеры, точку привязки и число кадров**. Если финальный арт нарисуют в другой сетке или с другим origin, придётся править не картинки, а код всех View-нод. Пайплайн фиксируется до первого нарисованного пикселя.

## 1. Константы, которые фиксируются один раз и навсегда

| Что | Значение | Откуда |
|---|---|---|
| Тайл | **32×32** | docs/00 §3, `WorldGeo.TILE` |
| Ярус | **3 тайла = 96 px** | `WorldGeo.PX_PER_MARK` |
| Агент | **16×24** | промпт 05 |
| Существо | **32×24** | промпт 09 |
| Мировой вьюпорт | **640×360** | промпт 00 |
| Иконки ресурсов | **16×16** | промпт 12 |
| Палитра | **32 цвета** | ТЗ |
| Родной кегль шрифта | **12 px** | research/28 §2 |

⚠️ **Origin (точка привязки) спрайтов — это контракт, а не вкус.**
- **Агент и существа: origin = низ-центр** (ноги на земле). В Godot: `Sprite2D.centered = false` + `offset = Vector2(-w/2, -h)`, либо `centered = true` + `offset.y = -h/2`. **Выбрать одно и записать**, иначе половина спрайтов утонет в полу.
- **Постройки: origin = низ-лево** клетки, потому что `can_place` работает от левого-верхнего угла и опоры под нижним рядом (research/17 §2).
- **Тайлы: origin — угол клетки**, `map_to_local` возвращает **центр** (research/12 §1) — компенсировать в одном месте.

⚠️ **Ширина спрайтов — чётная.** При `centered = true` и нечётной ширине `flip_h` смещает картинку на 1 px (research/15 §6.4). 16 и 32 — чётные, это не случайность.

## 2. Aseprite → Godot: три способа и выбор

| Способ | Как | Плюсы | Минусы |
|---|---|---|---|
| **A. Ручной экспорт PNG** | File → Export Sprite Sheet | ноль зависимостей | ручная работа при каждой правке; забытый реэкспорт |
| **B. Плагин-импортёр** | [Aseprite Wizard](https://github.com/viniciusgerevini/godot-aseprite-wizard) | `.aseprite` → `SpriteFrames`/`AnimationPlayer` прямо в редакторе, теги → анимации, длительности кадров конвертируются | зависимость-аддон; нужен установленный Aseprite |
| **C. CLI + скрипт** | `aseprite --batch --sheet` в `tools/export_art.sh` | воспроизводимо, годится для CI | больше кода; лицензия Aseprite нужна на машине сборки |

**Рекомендация: B как основной, C как страховка для CI.**

**Aseprite Wizard даёт ровно то, что нам нужно:**
- создаёт `SpriteFrames` с `AtlasTexture` — один PNG на персонажа, никакого дробления на файлы;
- **конвертирует длительность кадра Aseprite (мс) в FPS Godot** — иначе это ручная арифметика при каждой правке;
- **каждый тег Aseprite → отдельная анимация**; без тегов — одна `default`;
- фильтрует слои по regex (можно держать в файле служебные слои — сетку, направляющие — и не тащить их в игру);
- поддерживает направления Aseprite (forward/reverse/ping-pong) и зацикленность через repeat/теги.

⚠️ **Обязательное соглашение о тегах** (иначе анимации будут называться как попало и код развалится):
```
idle · walk · work · rest · panic · drown · dead
```
Ровно эти имена, строчными, без пробелов. **Записать в `assets/sprites/README.md` как контракт для художника.**

**CLI-вариант для `tools/export_art.sh`:**
```bash
#!/usr/bin/env bash
# Пакетный реэкспорт всего арта. Нужен, если художник не работает в Godot.
set -e
ASE="${ASEPRITE:-aseprite}"
SRC="art"          # исходники .aseprite, ВНЕ res:// (иначе поедут в билд)
DST="godot/assets/sprites"

for f in "$SRC"/agents/*.aseprite; do
  name=$(basename "$f" .aseprite)
  "$ASE" --batch "$f" \
    --ignore-layer "_guide" \
    --sheet "$DST/agents/$name.png" \
    --sheet-type horizontal \
    --data "$DST/agents/$name.json" --format json-array \
    --list-tags --trim=false --inner-padding 0
done
```
⚠️ **`--trim=false` и `--inner-padding 0` обязательны.** Триминг сдвигает кадры относительно origin и ломает привязку ног к земле; padding в пиксель-арте не нужен (мы не фильтруем текстуры, `Nearest` не размывает соседей).

⚠️ **Исходники `.aseprite` держать ВНЕ `res://`** — в папке `art/` рядом с `godot/`. Иначе они уедут в билд (research/26 §2.2) или Godot попытается их импортировать. Если хочется хранить рядом — исключить фильтром экспорта.

## 3. Палитра из 32 цветов: как хранить и как применять

### 3.1 Источник правды
**Один файл `art/tidebound.gpl`** (формат GIMP palette — читается Aseprite, Krita, Photoshop через плагин, и это plain text, который диффится в git):
```
GIMP Palette
Name: Tidebound 32
Columns: 8
#
 27  38  50	ink
238 232 213	paper
 43  59  71	panel_bg
201 148  74	accent
...
```

### 3.2 Как она попадает в код
⚠️ **Не копировать HEX руками в `tokens.gd`.** Это два источника правды, они разъедутся.

**Генератор (одноразовый `EditorScript`, тот же приём, что для `.tres` в research/14 §3):**
```gdscript
@tool
extends EditorScript
## tools/gen_palette.gd — .gpl -> ui/theme/palette.gd. File → Run после правки палитры.

func _run() -> void:
	var src := FileAccess.open("res://../art/tidebound.gpl", FileAccess.READ)
	var out: PackedStringArray = ["class_name Palette", "## АВТОГЕНЕРАЦИЯ. Правь art/tidebound.gpl.", ""]
	while not src.eof_reached():
		var line: String = src.get_line().strip_edges()
		if line.is_empty() or line.begins_with("#") or line.begins_with("GIMP") \
				or line.begins_with("Name:") or line.begins_with("Columns:"):
			continue
		var parts: PackedStringArray = line.split("\t", false)
		if parts.size() < 2: continue
		var rgb: PackedStringArray = parts[0].split(" ", false)
		var name: String = parts[1].strip_edges().to_upper()
		out.append("const %s := Color8(%s, %s, %s)" % [name, rgb[0], rgb[1], rgb[2]])
	FileAccess.open("res://ui/theme/palette.gd", FileAccess.WRITE)\
		.store_string("\n".join(out) + "\n")
	print("палитра: %d цветов" % (out.size() - 3))
```
Тогда `UITokens` ссылается на `Palette.ACCENT`, а не на литерал — и правка палитры художником меняет UI целиком после одного запуска билдера темы (research/19 §2).

### 3.3 Проверка «в палитре ли арт»
```gdscript
# tests/test_art_palette.gd — ловит цвета, которых нет в палитре
static func test_palette_compliance(t: TestCtx) -> void:
	var allowed: Dictionary[int, bool] = {}
	for c: Color in Palette.ALL:
		allowed[c.to_rgba32()] = true
	for path: String in _all_pngs("res://assets/sprites/"):
		var img: Image = (load(path) as Texture2D).get_image()
		for y: int in img.get_height():
			for x: int in img.get_width():
				var px: Color = img.get_pixel(x, y)
				if px.a < 0.5: continue
				t.check(allowed.has(px.to_rgba32()),
					"%s (%d,%d): цвет %s вне палитры" % [path, x, y, px.to_html()])
```
⚠️ Тест медленный — гонять **не в общем прогоне**, а отдельным сьютом (`tests/art/`) или раз в этап. Но он единственный, кто ловит «художник сохранил в RGB и подмешал антиалиасинг».

⚠️ **Полупрозрачных пикселей быть не должно вовсе** — только `a = 0` или `a = 255`. Полупрозрачность в пиксель-арте — почти всегда следствие случайного антиалиасинга кисти. Добавить в тот же тест.

### 3.4 Перекраска через палитру (indexed palette swap)
Если понадобится вариативность агентов (разный цвет одежды) без новых спрайтов — стандартный приём: спрайт в **индексных цветах**, шейдер меняет индексы на цвета из 1D-текстуры.
⚠️ **Не делать на этапах 02–09.** Это оптимизация ассетов, она имеет смысл только когда спрайтов много. У нас 6 агентов; проще нарисовать 6 вариантов. Записать в backlog.

## 4. Атласы

**В Godot 4 нет встроенного упаковщика атласов при импорте** (в 3.x был тип импорта «Atlas», в 4.x его нет). Варианты:

| Что | Как | Когда |
|---|---|---|
| **Спрайт-лист на сущность** | Aseprite Wizard делает `SpriteFrames` + `AtlasTexture` | **наш основной путь** для агентов/существ |
| **Тайлсет** | `TileSetAtlasSource` из одного PNG (research/12 §2) | тайлы |
| **UI-атлас** | один `ui_atlas.png` + `AtlasTexture`-регионы вручную/скриптом | этап 18 п.8 |
| Сторонний упаковщик (TexturePacker, free-tex-packer) | внешний JSON → скрипт генерации `AtlasTexture` | ⚠️ избыточно при нашем объёме |

**Полезно из 4.7:** `AtlasTexture` теперь **тайлится в `TextureRect`** (research/00 §6) — значит 9-patch-рамки UI можно резать прямо из общего атласа без отдельных файлов. Это ровно то, что нужно этапу 18 п.8.

⚠️ **Не гнаться за одним атласом на всё.** Выгода атласа — меньше смен текстуры за кадр. У нас на экране единицы текстур и сотни нод; узким местом это не будет никогда (research/15 §6.6). Атлас нужен **для удобства скина UI**, а не ради производительности.

## 5. `AnimationPlayer` или `AnimatedSprite2D` для агента 16×24

| | `AnimatedSprite2D` + `SpriteFrames` | `AnimationPlayer` |
|---|---|---|
| Что умеет | последовательность кадров, FPS, луп | **любые** свойства + вызовы методов + сигналы |
| Код | `sprite.play("walk")` | `anim.play("walk")` |
| Ноды | 1 | 2 (Sprite2D + AnimationPlayer) |
| Смешивание с кодом | легко | легко |
| Событие «на кадре N» | ⚠️ нет из коробки | **Call Method Track** |
| Привязка к нашему `sim_time` | вручную | вручную |

**Рекомендация: `AnimatedSprite2D` для агента, существ и построек.**

Обоснование:
1. Нам нужна **только смена кадров**. Ни костей, ни синхронных изменений нескольких свойств.
2. Промпт 05 требует программную «покачивание»-заглушку, промпт 18 — 4 кадра ходьбы + 2 кадра работы. Это ровно `SpriteFrames`.
3. `AnimationPlayer` понадобился бы ради Call Method Track («звук шага на 2-м кадре») — но **звук шагов у нас не запланирован** (docs/00 §15), а событийные звуки идут от `Events` (research/23 §5).

⚠️ **Одно исключение — UI.** Для сложной анимации панелей (`RunSummary` с «подъездом» чисел) `AnimationPlayer` удобнее Tween'ов. Но промпт 15 уже описывает это через Tween (research/21 §3) — и это правильно, потому что Tween легко прервать тапом.

### 5.1 Скорость анимации должна идти от `sim_time`, а не от `TIME`
```gdscript
# agent_view.gd
func _process(_d: float) -> void:
	# Пауза видна: на speed=0 анимация замирает. Тот же принцип, что у шейдеров (research/05)
	sprite.speed_scale = 0.0 if Game.speed == 0 else float(Game.speed)
```
⚠️ **`speed_scale = 0` останавливает `AnimatedSprite2D` корректно** (в отличие от частиц — там баг #77916, research/00 §8, и нужен `PROCESS_MODE_DISABLED`).

### 5.2 Контракт кадров (для художника)
```
agent_<name>.aseprite
├── tag "idle"  — 2 кадра, 500 мс каждый
├── tag "walk"  — 4 кадра, 120 мс
├── tag "work"  — 2 кадра, 200 мс
├── tag "rest"  — 2 кадра, 600 мс
└── tag "dead"  — 1 кадр
Размер холста: 16×24. Origin: низ-центр. Направление: смотрит ВПРАВО
(влево получается через flip_h — рисовать только одну сторону).
```
⚠️ **«Рисовать только вправо»** — экономия вдвое и требование к художнику. Асимметричные детали (инструмент в одной руке) при флипе перескочат — это допустимо на 16×24 и это надо проговорить заранее, а не обнаружить на этапе 18.

## 6. Готовые ассет-паки: где граница «купить / нарисовать»

### 6.1 Что можно взять готовым

| Категория | Реалистично взять готовым | Почему |
|---|---|---|
| Тайлы камня/песка/воды | ✅ | генерические, легко перекрасить в свою палитру |
| Иконки ресурсов 16×16 | ✅ частично | 13 предметов — типовые (рыба, доска, слиток, верёвка) |
| UI-рамки, кнопки, 9-patch | ✅ | Kenney и подобные — CC0, качественно |
| Шрифт | ✅ | research/28 |
| **Агенты 16×24 с 5 анимациями** | ❌ | набор состояний уникален (тонет, паника, отдых) |
| **17 построек в разрезе утёса** | ❌ | форма продиктована механикой (шлюз, испаритель, помост) |
| **Существа Прихода** | ❌ | это лицо игры |
| **Утёс в разрезе с ярусами** | ❌ | геометрия жёстко привязана к 3 тайлам на ярус |

**Правило границы:** покупать/брать можно то, что **не несёт механики и не задаёт силуэт игры**. Всё, что игрок опознаёт как «это TIDEBOUND», рисуется своё.

### 6.2 Лицензии — что проверять
| Лицензия | Можно в коммерческой игре | Атрибуция | Ловушка |
|---|---|---|---|
| **CC0** | да | не требуется | — |
| **CC-BY 4.0** | да | **обязательна** | забыть кредиты = нарушение |
| CC-BY-SA | ⚠️ да, но | обязательна | **вирусная**: производные под той же лицензией — опасно для арта, который вы дорисуете |
| CC-BY-NC | **нет** | — | NC = некоммерческая, для Steam не годится |
| itch «Asset pack», «commercial use allowed» | обычно да | по-разному | ⚠️ читать текст на странице, а не заголовок; сохранять копию условий |
| OFL 1.1 (шрифты) | да | сохранить лицензию | нельзя продавать сам шрифт отдельно |

⚠️ **Заводить `assets/CREDITS.md` с первого же заимствованного файла:** источник, автор, лицензия, ссылка, дата скачивания. Восстанавливать это за неделю до релиза — ад. Файл же идёт в экран титров.

⚠️ **Сохранять локальную копию текста лицензии** рядом с ассетом: страницы itch исчезают, авторы меняют условия.

**Ориентиры CC0-источников:** [Kenney](https://kenney.nl) (UI, иконки, генерические тайлы), OpenGameArt (⚠️ лицензии смешанные — проверять каждый файл), itch.io asset packs (⚠️ читать условия).

### 6.3 Оценка объёма собственного арта
```
тайлсет утёса (камень/песок/руины + кромки)   ~24 тайла
агент 16×24 × 5 анимаций                      ~11 кадров × 1–2 варианта
существо 32×24 × 2 анимации                   ~6 кадров
17 построек (статичные, 1–2 кадра)            ~25 кадров
13 иконок 16×16                               13
UI-атлас (рамки, кнопки 3 состояния, иконки)  ~1 лист
фон-параллакс 3 слоя                          3
```
Это **порядка 90–110 кадров** — 2–4 недели работы одного пиксель-артиста средней руки, либо покупаемая работа. **Заглушки этапов 02–09 должны быть достаточно точными по размерам и origin, чтобы финальный арт вставал без правки кода.**
