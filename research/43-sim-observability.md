## 1. Разбор дела о соли: чего именно не хватало

Полезно посчитать, какой инструмент сократил бы какой прогон.

| Прогон | Что делали руками | Чем заменяется |
|---|---|---|
| 1. «соль появляется раз за забег» | печать `totals()` по циклам | **`run_until`**: остановиться, когда `salt` вырастет во второй раз — сразу видно, что не наступает |
| 2. по фазам | печать на каждой границе | **дамп на границах фаз** + дифф между ними |
| 3. по флагам `flooded_in_phase`, `is_working` | добавили печать в три места | **трассировка станции**: `idle_reason` уже есть, не хватает журнала его изменений |
| 4. шаг 20 тиков в окне 4940–5100 | цикл с печатью | **дифф двух снимков** т4940 vs т5100 с маской шума |
| 5. изолированный сценарий | отдельный тест | ⚠️ **это правильная работа**, её ничем не заменить — но она должна была быть **первой**, а не пятой |

⚠️ **Главный вывод не про инструменты, а про метод.** Четыре прогона ушли на то, чтобы понять, что проблема **не в испарителе**. Изолированный сценарий («тот же объект без окружения») дал ответ за один прогон. **Правило: при расхождении «работает в изоляции, не работает в игре» первым делом строится изолированный сценарий, а не печать в полном.**

## 2. Дамп и дифф состояния

### 2.1 Почему `to_dict()` недостаточно как есть

`SimWorld.to_dict()` уже даёт полный снимок — это большое преимущество, у большинства проектов такого нет. Но напрямую для отладки он непригоден:

- ⚠️ **Простыня.** 6 агентов × ~30 полей + постройки + склады + задачи + депозиты ≈ **несколько сотен строк JSON**. Глазами не сравнить.
- ⚠️ **Шум.** Между двумя соседними тиками меняются: `x` каждого агента, `need_rem` (остатки накопления), `tick_in_phase`, `total_ticks`, `state_ticks`, `work_ticks`, `_ticks_since_emit`. Это **десятки изменившихся полей на каждом тике**, среди которых тонет одно интересное.
- ⚠️ **Нет адресов.** Чтобы сказать «изменился буфер станции 4», нужен путь вида `buildings/4/buffer/salt`, а не вложенный словарь.

### 2.2 Что добавить: плоский дифф с маской

```gdscript
var a: Dictionary = SimDump.flat(world)          # {"clock/cycle": 2, "buildings/4/buffer/salt": 1, ...}
t.run_ticks(world, 300)
var b: Dictionary = SimDump.flat(world)
print(SimDump.diff_text(a, b))
```
```
[buildings]
  4/buffer/salt          1 → 0
  7/progress_ticks       0 → 143
[storage]
  0/stacks/3/count       8 → 10
[run_state]
  score_snapshot         {} → {cargo:14, survivors:30, relics:0}
```

**Три решения, которые делают дифф читаемым:**

1. **Маска шума — по умолчанию включена.** Список путей-шаблонов, которые дифф игнорирует: `agents/*/x`, `agents/*/need_rem/*`, `*/state_ticks`, `clock/total_ticks`, `*/ticks_since_emit`. Флагом `full = true` — показать всё.
2. **Числовой порог.** Изменение `float` меньше 0.01 не показывать: иначе `tide/level` мельтешит в каждом диффе. ⚠️ У нас всё квантовано до 1e-4 (`Balance.quant`), так что порог безопасен.
3. **Группировка по системе.** Дифф печатается разделами `clock / tide / terrain / storage / agents / jobs / buildings / production / crisis / run_state` — сразу видно, **какая система** изменилась, ещё до чтения строк.

### 2.3 Дамп «в момент X»

```gdscript
SimProbe.dump_at(world, [1949, 1960, 2249], "user://dumps/")   # снимки по списку тиков
```
Ровно та таблица, которая в `BUG-salt-chain.md` собиралась руками. Файлы кладутся рядом и сравниваются любым внешним дифф-инструментом.

⚠️ **Дампы — в `user://`, а не в `res://`**: они большие, генерируются часто и не должны попадать ни в git, ни в билд.

## 3. Реплей: что есть и чего не хватает

### 3.1 Что уже есть

`SimWorld.replay(seed_value, log, until_tick, cliff)` (написан на этапе 01) плюс `command_log`, пишущийся при `record = true`. Это **сильнее, чем у большинства проектов**: сид + журнал команд воспроизводят забег целиком.

### 3.2 Чего не хватает — три вещи

| Нужно | Зачем | Дней |
|---|---|---|
| **Персистентность журнала** | сейчас `command_log` не попадает в `to_dict()` — после `save → load` воспроизвести нельзя ([ARCH-08](../review/03-architecture-risks.md)) | 0.5 |
| **`run_until(predicate)`** | ⚠️ **главное, чего не хватало в деле о соли** | 0.5 |
| **Пошаговое исполнение** | «ещё один тик» + печать диффа | 0.5 |

### 3.3 `run_until` — почему это ключевой инструмент

```gdscript
## Прогоняет мир, пока предикат не станет истинным. Возвращает тик или −1.
## Проверка ПОСЛЕ каждого тика: условие «соль появилась» ловится в тот же тик.
static func run_until(w: SimWorld, cond: Callable, max_ticks: int = 60000) -> int
```

Как это выглядит в деле о соли:

```gdscript
# «Когда соль появится во второй раз?»
var seen: int = 0
var t: int = SimProbe.run_until(w, func(world: SimWorld) -> bool:
	var s: int = int(world.storage.totals().get("salt", 0))
	if s > seen:
		seen = s
	return seen >= 2)
print("вторая соль на тике ", t)      # −1 → не появляется вообще. Один прогон, один ответ.
```

**Готовые предикаты, которые понадобятся в `FIX-review` постоянно:**

| Предикат | Находка ревью |
|---|---|
| `w.agents.alive_count() < 6` | первая смерть — SIM-07, TEST-10 |
| `w.run_state.ship_arrived` | **SIM-01**, момент снятия очков |
| `world_resources(w) > before` | **SIM-02** — ресурсы из воздуха при сносе |
| `ProductionSystem.idle_reason(b, w) != ""` | простой станции |
| `Game.error_count() > 0` | любой необработанный `SimEvent` |

## 4. Трассировка решений

Главных вопросов отладки этой игры два, и оба про «почему».

### 4.1 «Почему агент выбрал это, а не то»

`JobSystem._best_job_for` перебирает задачи и считает `score()`. Наружу выходит только победитель.

```gdscript
## Включается флагом; в обычном прогоне — ноль работы.
if SimTrace.enabled:
	SimTrace.job_choice(a.id, w.clock.total_ticks(), candidates, best_id)
```
```
т4820 агент 3 выбрал job#41 (gather, депозит 7, score 187)
  отброшено: job#38 gather score 203 — GREED (14.0 > 8 тайлов от лестницы)
             job#44 haul   score 190 — недостижим
             job#52 eat    score 155 — satiety 78 > EAT_WANT
```

**Три правила, чтобы это не мешало:**

1. ⚠️ **Никаких строк в горячем пути при выключенной трассировке.** `if SimTrace.enabled:` перед любой конкатенацией — форматирование дороже самого решения.
2. ⚠️ **Причина отказа — код, а не строка.** `_greed_allows`, `_reachable`, `_applies_to` возвращают `bool`; чтобы знать причину, нужен отдельный `reject_reason(a, j, w) -> int`, вызываемый **только при включённой трассировке**.
3. **Кольцевой буфер, а не файл.** 500 последних решений в памяти; сброс в файл по команде. Иначе за забег набежит десяток мегабайт.

### 4.2 «Почему станция стоит»

`ProductionSystem.idle_reason(b, w)` **уже написан** (появился вместе со `StationPanel`) — это ровно то, что нужно. Не хватает **журнала его изменений**:

```gdscript
# В ProductionSystem.tick, при включённой трассировке:
var r: String = idle_reason(b, w)
if r != str(b.get("_last_reason", "")):
	b["_last_reason"] = r
	SimTrace.station(int(b["id"]), w.clock.total_ticks(), r)
```
```
т1949 станция 4 (evaporator): "" → работает
т2100 станция 4 (evaporator): flooded
т4940 станция 6 (saltery):    no_materials      ← вот оно
```

⚠️ В деле о соли причина `no_materials` **была известна** — но не было видно, **с какого тика** она держится и что случилось прямо перед этим. Журнал изменений отвечает на оба вопроса одной строкой.

### 4.3 Что НЕ трассировать

- ⚠️ **Не логировать каждый тик каждого агента.** 6 агентов × 36 000 тиков = 216 000 записей за забег. Логировать **смены**: состояния, задачи, причины простоя.
- Не трассировать движение — для него есть оверлей пути (§6).
- Не писать трассу из `sim/` в файл: `SimTrace` — статический приёмник, `sim/` только зовёт его. ⚠️ Формально это единственная уступка правилу «sim ничего не знает о внешнем мире»; она допустима, потому что приёмник — чистые данные, без нод и без `Time.*`.

## 5. Дефект класса «зелёные тесты при 365 ошибках»

**Самая дешёвая правка во всём документе и самая важная.**

`buffer_take` падал **на каждом вызове** одиннадцать этапов подряд. Раннер этого не видел: он проверяет только собственные `check()`, а `SCRIPT ERROR` в stderr для него невидим.

### 5.1 Механизм: свой `Logger`

Godot **4.5+** даёт класс `Logger` и `OS.add_logger()`. Логгер получает **все** сообщения, включая рантайм-ошибки скриптов (`research/36 §1.3`).

```gdscript
class_name ErrorGuard
extends Logger

static var errors: int = 0
static var first: String = ""

func _log_error(function: String, file: String, line: int, code: String,
		rationale: String, editor_notify: bool, error_type: int,
		script_backtraces: Array) -> void:
	errors += 1
	if first.is_empty():
		first = "%s:%d %s (%s)" % [file, line, code, rationale]
```

Регистрируется в `_initialize()` раннера, **до** прогона сьютов:
```gdscript
OS.add_logger(ErrorGuard.new())
...
if ErrorGuard.errors > 0:
	print("TESTS FAILED: %d ошибок движка, первая: %s" % [ErrorGuard.errors, ErrorGuard.first])
	quit(1)
```

⚠️ **Док прямо предупреждает: логгер вызывается из других потоков.** Внутри — только инкремент счётчика и запись строки, никаких обращений к дереву нод.

⚠️ **Сигнатура `_log_error` длинная и версионно-зависимая.** Проверить по class reference своей версии перед переносом; `⚠️ НЕ ПОДТВЕРЖДЕНО` для 4.7 — набор аргументов уточнялся между 4.5 и 4.6.

### 5.2 Запасной вариант, который работает сегодня и без кода

Раннер запускается скриптом; stderr проверяется снаружи:
```bash
godot --headless -s res://tests/run_all.gd 2> build/test_stderr.log
if grep -q "SCRIPT ERROR" build/test_stderr.log; then
    echo "❌ SCRIPT ERROR: $(grep -c 'SCRIPT ERROR' build/test_stderr.log) шт."
    grep -m3 -A2 "SCRIPT ERROR" build/test_stderr.log
    exit 1
fi
```
⚠️ Грубее (не показывает, какой тест), но **добавляется в `tools/test.sh` за пять минут**. Делать немедленно, независимо от §5.1.

### 5.3 Что ещё ловится этим же приёмом

| Класс дефекта | Как проявляется | Ловится |
|---|---|---|
| Ошибка типизации в рантайме (`buffer_take`) | SCRIPT ERROR на каждый вызов | ✅ |
| `push_error` из `_flush_events` (событие без маппинга) | ⚠️ счётчик `Game._error_count` есть, но **никто его не читает** | ✅ |
| `push_error` из `DB` (нет дефа) | ошибка | ✅ |
| Обращение к `null`-дефу ([ARCH-07](../review/03-architecture-risks.md)) | краш | ✅ |
| Несовместимая сигнатура обработчика сигнала | warning только в debug-сборке | ⚠️ частично |

⚠️ **`Game._error_count` существует с этапа 01 специально ради этой проверки — и ни один тест его не читает.** Одна строка в `TestCtx.print_report`.

## 6. Визуальный дебаг поверх мира

`debug/debug_overlay.gd` уже даёт: граф навигации, отметки ярусов, остатки депозитов, зону затопления. Написан правильно — живёт внутри `World`, перерисовывается по событиям, при выключенных флагах не делает ничего.

**Чего не хватает — три оверлея, каждый отвечает на конкретный вопрос:**

| Оверлей | Отвечает на вопрос | Как рисовать |
|---|---|---|
| **Пути агентов** | «куда он идёт и почему так далеко» | `draw_polyline` по `a.path` через позиции узлов AStar; цвет по состоянию |
| **Резервирования задач** | «почему задачу никто не берёт» / «почему двое идут в одно место» | линия агент → `job.cell`, подпись `job.id`; свободные задачи — точкой |
| **Зона фильтра Жадности** | ⚠️ **самый ценный**: делает видимым правило, которое сейчас невидимо | заливка клеток, где `nearest_ladder_dist <= limit` |

⚠️ Третий стоит того, чтобы попасть **не только в дебаг**: по разбору [39 §7.1](39-design-critique.md) игрок не понимает Жадность именно потому, что её граница невидима. Отладочный оверлей — готовая заготовка для игровой подсказки (идея `D-3`).

**Ещё два, дешёвых:**
- **Тепловая карта посещений** — где агенты реально ходили за забег. Отвечает на «используется ли эта часть карты вообще» (нужно балансу, `research/30`).
- **Метка `idle_reason` над станцией** — то, что уже посчитано для `StationPanel`.

## 7. Тест-хелперы: чтобы тест писался в три строки

`TestCtx` уже имеет `check`, `check_eq`, `check_approx`, `check_hash`, `run_ticks`, `find_divergence`, `state_hash`. Для `FIX-review` не хватает шести.

| Хелпер | Заменяет | Для находок |
|---|---|---|
| `run_until(w, cond, max)` | цикл с проверкой | все |
| `world_resources(w) -> Dictionary` | ручной обход складов + земли + буферов + котомок | **SIM-02**, SIM-03 |
| `check_no_resource_gain(before, after)` | сравнение двух словарей | SIM-02 |
| `snapshot(w)` / `check_unchanged(snap, w, mask)` | «ничего лишнего не изменилось» | ARCH-05, регрессии |
| `check_events(w, "type", n)` | ручной подсчёт `events_out` | SIM-06, TEST-04 |
| `place_and_build(w, def_id, cell)` | 15 строк подготовки станции | все тесты производства |

**Пример: тест на SIM-02 (снос недостроенного) в три строки**
```gdscript
static func test_demolish_planned_creates_nothing(t: TestCtx) -> void:
	var w: SimWorld = t.fixture_world(29)
	var before: Dictionary = t.world_resources(w)
	var id: int = w.buildings.place("forge", t.cell_on(3, 4), w)   # остаётся PLANNED
	w.buildings.demolish(id, w)
	t.check_no_resource_gain(before, t.world_resources(w), "снос недостроя создал ресурсы")
```

⚠️ **`world_resources` — самый важный из шести.** Он считает **все** ресурсы мира: склады + земля + буферы построек + котомки агентов. Целый класс находок ревью («ресурсы возникают или исчезают») проверяется одним сравнением до/после. Сейчас каждый такой тест пишет свой обход — и каждый забывает про буферы.

## 8. Как это делают в других симуляциях

Что стоит одного дня, а что нет.

| Игра | Инструмент | Стоит ли нам | Почему |
|---|---|---|---|
| **RimWorld** | **Toggle job logging** — журнал выбора работы пешкой | ✅ **да** | это ровно §4.1; их опыт подтверждает, что «почему выбрал» — вопрос №1 |
| RimWorld | **Draw pawn debug / Draw Duties** — состояние поверх пешки | ✅ да | наши метки состояний уже есть в `agent_view`; добавить `job.id` |
| RimWorld | Инспектор объекта, dev palette, god mode | ⚠️ частично | инспектор дублирует `StationPanel`/`AgentCard`; god mode — это `level_override`, уже есть |
| **Factorio** | **F5 — переключение оверлеев отладки** | ✅ да | одна клавиша вместо меню; у нас F1 → панель → чекбоксы, это на два действия дольше |
| Factorio | `/editor` — редактор мира на паузе | ❌ нет | карта задана вручную в `CliffDef`, редактировать нечего |
| **ONI** | Backspace — меню отладки: спавн, копирование, разрушение | ⚠️ частично | спавн ресурсов и построек в дебаг-панель полезен для сценариев; остальное нет |
| Dwarf Fortress | Доступ к внутренностям через DFHack | ❌ нет | экосистема поверх закрытой игры; у нас исходники свои |

⚠️ **Общий вывод из чужого опыта:** все четыре игры имеют **журнал выбора ИИ** и **переключаемые оверлеи по одной клавише**. Ни у одной нет того, что есть у нас, — **полного детерминированного снимка состояния**. Наш дифф (§2) сильнее их инструментов; не хватает именно этих двух.

## 9. Порядок внедрения

Первые три пункта закрывают дело о соли и класс `buffer_take`; их стоит сделать **до** ремонтного прохода.

## 10. Чек-лист

**Немедленно, до ремонтного прохода:**
- [ ] `tools/test.sh` валит прогон при `SCRIPT ERROR` в stderr.
- [ ] `TestCtx.print_report` печатает `Game.error_count()` и валит прогон при ненулевом.
- [ ] `run_until(w, cond)` и `world_resources(w)` есть в `TestCtx`.

**Перед балансировкой:**
- [ ] `SimDump.flat()` даёт плоские пути; маска шума включена по умолчанию.
- [ ] `SimDump.diff_text(a, b)` группирует по системам и скрывает изменения `float` < 0.01.
- [ ] `SimProbe.dump_at(w, [тики], dir)` пишет снимки в `user://dumps/`.
- [ ] `SimTrace` выключен по умолчанию; при выключенном — ноль форматирования строк в горячем пути.
- [ ] Журнал `idle_reason` пишется только на смену значения.
- [ ] `command_log` переживает `save → load` (или лежит отдельным файлом рядом).

**Оверлеи:**
- [ ] Пути, резервирования и зона Жадности переключаются **одной клавишей** (как F5 в Factorio), а не через панель.
- [ ] При всех выключенных оверлеях `_draw` выходит сразу (уже так).

**Дисциплина, а не код:**
- [ ] При расхождении «работает в изоляции, не работает в игре» **первым** строится изолированный сценарий, а не печать в полном (§1).
- [ ] Дампы пишутся в `user://`, не попадают в git и в билд.
