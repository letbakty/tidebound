## 1. Контекст: что Godot починил в 2025–2026 и что это значит

Godot Foundation в апреле 2026 отчиталась о работе по мобильной стабильности, основанной на данных двух реальных релизов — **Kamaeru: A Frog Refuge** и **Rift Riff** (обе вышли на мобильных сторах в декабре 2025).

Что было сделано:
- исправлено **использование Vulkan API** самим движком;
- найдены **обходные пути для сломанных драйверов GPU** — конкретно **Mali и Adreno**;
- разобраны краевые случаи «длинного хвоста» Android-устройств.

Результат: **краш-рейт обеих игр упал с ~4% до менее 1%**. Исправления вошли в **4.5.2 и 4.6**.

**Три вывода для нас:**
1. ⚠️ **Использовать 4.7.x — не роскошь, а требование.** Все эти фиксы уже внутри. Откат на 4.4 ради чего-либо вернёт 4% крашей.
2. ⚠️ **~4% крашей на старте — это норма для Godot-игры на Android без специальной работы.** Планировать мобильный релиз без прогона на реальных устройствах бессмысленно.
3. **Инфраструктура для диагностики появилась:** нативные debug-символы для Android (4.5+), инструментальные тесты через Firebase Test Lab (4.6+), трассировка через Perfetto. То есть краши теперь **можно читать**, а не гадать.

⚠️ Статья Foundation **не содержит** рекомендаций по выбору рендерера, фолбэку на Compatibility и по стоимости screen-read шейдеров. Всё в §2–§4 ниже — инженерный анализ и общеизвестные свойства мобильных GPU, а не цитаты из документации. Помечено соответственно.

## 2. Главный технический риск: бэкбуфер на тайловом GPU

⚠️ **НЕ ПОДТВЕРЖДЕНО документацией Godot; это свойство архитектуры мобильных GPU.**

Мобильные GPU (Mali, Adreno, PowerVR) — **тайловые** (TBR/TBDR). Кадр рисуется по тайлам в быстрой on-chip памяти, и результат сбрасывается в основную память **один раз в конце прохода**.

`hint_screen_texture` требует **прочитать уже отрисованный кадр**. Это заставляет драйвер:
1. завершить текущий проход и **сбросить тайлы в память** (resolve);
2. скопировать результат в текстуру;
3. **начать новый проход**, заново загрузив тайлы.

На десктопе (immediate-mode GPU) это дешёвая операция копирования. **На тайловом GPU это разрыв конвейера** — самая дорогая вещь, которую можно сделать в мобильном рендере.

**Что это значит для research/01 (шейдер воды с рефракцией):**
- на десктопе и Deck — не проблема;
- на телефоне — **потенциально главный расход кадра**, и он не зависит от того, насколько сложен сам шейдер: платим за факт чтения экрана;
- ⚠️ вода занимает **половину экрана** (research/01), то есть площадь копии максимальная.

### 2.1 План А (замерить) и план Б (готовый обход)

**План А — замер.** До этапа 18, на этапе 02–03:
1. Положить на `WaterRect` временный шейдер, который **только** читает экран и возвращает прочитанное (`COLOR = textureLod(screen_tex, SCREEN_UV, 0.0)`).
2. Снять fps на целевом устройстве с ним и без него.
3. Разница и есть цена бэкбуфера. Если она > 2–3 мс — план Б.

```glsl
// assets/shaders/_bench_backbuffer.gdshader — временный, для замера
shader_type canvas_item;
uniform sampler2D screen_tex : hint_screen_texture, repeat_disable, filter_nearest;
void fragment() {
	COLOR = textureLod(screen_tex, SCREEN_UV, 0.0);
}
```

**План Б — вода без чтения экрана.** Тот же приём, что для веба (research/31 §2.2): отдельный `water_mobile.gdshader`, в котором вместо рефракции:
- вертикальный градиент прозрачности (есть и так);
- **искажение геометрией, а не пикселями**: синус в `vertex()` по `VERTEX.y` — деформируется сам прямоугольник воды, экран не читается;
- пена по кромке — процедурная, от `sim_time`;
- рябь — наложение полупрозрачных полос, `blend_mix`.

⚠️ **Визуально это заметно проще**, но «дорогой» вид на телефоне всё равно делает не рефракция, а **свет и цвет** (research/02): тёплые огни против холодного низа читаются на 6-дюймовом экране лучше, чем искажение на 2 пикселя.

**Выбор материала:**
```gdscript
# water_view.gd
func _ready() -> void:
	var path: String = "res://assets/shaders/water.gdshader"
	if OS.has_feature("mobile") or OS.has_feature("web"):
		path = "res://assets/shaders/water_lite.gdshader"
	(material as ShaderMaterial).shader = load(path)
```
⚠️ **Один `water_lite.gdshader` на мобилки и веб** — не два. Требования совпадают (нет screen-read), а поддерживать две упрощённые версии никто не будет.

⚠️ **Uniform'ы обеих версий должны совпадать по именам.** Тогда `water_view.gd` не знает, какой шейдер стоит, и не обрастает ветками. Это правило записать комментарием в обоих файлах.

## 3. Точность float и другие мобильные особенности шейдеров

⚠️ **НЕ ПОДТВЕРЖДЕНО для 4.7** — проверять на устройстве.

| Особенность | Проявление | Что делать |
|---|---|---|
| `mediump` по умолчанию на некоторых мобильных драйверах | волна «ступенчатит» на больших значениях `sim_time`; артефакты растут со временем сессии | **обнулять `sim_time` по модулю периода волны**: `fmod(t, 600.0)` — период кратен периоду синуса, разрыва не видно |
| Разная реализация `fract`/`mod` у драйверов | еле заметные швы | использовать `fract`, избегать `mod` с отрицательными аргументами |
| `texture()` с производными в ветвлении | undefined behavior на части драйверов | не вызывать `texture()` внутри `if` — считать заранее, смешивать `mix()` |
| Лимиты числа uniform'ов и varying | шейдер молча не компилируется на конкретном устройстве | держать число uniform'ов малым; **логировать ошибку компиляции шейдера в дебаг-панель** |
| Прекомпиляция шейдеров (shader baker, 4.5+) | первый кадр с новым материалом фризит | **feature-тег `shader_baker`** в 4.7 — включить для мобильных пресетов |

⚠️ **`sim_time` и переполнение — реальный риск нашей архитектуры.** research/05 задаёт `sim_time = tick/10 + accum`. За 12 циклов забега это 3600 секунд, за длинную сессию — больше. При `mediump` (10 бит мантиссы) точность на 3600.0 катастрофически падает. **Решение: отдавать в шейдер `fmod(sim_time, 1024.0)`** — 1024 кратно степени двойки и достаточно велико для всех наших периодов. **Это правка в `shader_time.gd` (research/code), сделать при переносе.**

## 4. Целевое устройство и что на нём мерить

**Redmi Note 11** — типичный «средний Android 2022 года», и это правильный выбор нижней планки:

| Модель | SoC | GPU | Заметка |
|---|---|---|---|
| Redmi Note 11 (global) | Snapdragon 680 | **Adreno 610** | Adreno — вторая из двух семей, чьи драйверы чинил Foundation |
| Redmi Note 11S | Helio G96 | **Mali-G57** | Mali — первая |

⚠️ **Уточнить, какая именно ревизия у вас на руках** — от этого зависит, какое семейство драйверов вы тестируете. В идеале иметь оба; если один — знать, что вторая половина рынка не проверена.

**Что мерить (и чем):**
1. **FPS в худшем кадре**: 12-й цикл, шторм, все фонари горят, вода на полэкрана, дождь. Не в меню.
2. **Цена бэкбуфера** — §2.1.
3. **Время тика симуляции** — уже есть график (research/13 §9). ⚠️ На мобиле GDScript медленнее; бюджет 2 мс может не выполняться, и это важно узнать до этапа 18.
4. **Термотроттлинг**: 15 минут непрерывной игры. Телефон, который держит 60 fps первую минуту и 25 — на десятой, для получасовых забегов не подходит.
5. **Краши**: Firebase Test Lab (поддержка инструментальных тестов с 4.6) прогонит билд на ферме устройств. ⚠️ Для нашего масштаба избыточно, но **нативные debug-символы Android (4.5+) включить обязательно** — иначе краш-репорты нечитаемы.

**Профилирование на Android:** Perfetto (системная трассировка) — то, что рекомендует Foundation. Встроенный профайлер Godot по сети тоже работает через remote debug.

## 5. Настройки проекта для мобильного билда

```
rendering/renderer/rendering_method = "mobile"
rendering/renderer/rendering_method.mobile = "mobile"
rendering/renderer/rendering_method.web = "gl_compatibility"     # research/31
application/run/max_fps.mobile = 60
rendering/anti_aliasing/quality/msaa_2d = 0
rendering/2d/shadow_atlas/size.mobile = 512                      # 8 светов, мелкий экран
```

⚠️ **Фолбэк на Compatibility для старых устройств.** Часть Android-устройств не даёт рабочего Vulkan. Godot умеет откатываться на OpenGL, но **это надо проверить**: при `rendering_method = mobile` и отсутствии Vulkan игра может не запуститься. ⚠️ **НЕ ПОДТВЕРЖДЕНО**, как именно 4.7 обрабатывает этот случай — проверить на реальном старом устройстве и, если нужно, собрать второй пресет с `gl_compatibility`.

⚠️ **`shader_baker`** (feature-тег в 4.7, research/26 §... — появился в списке тегов) — прекомпиляция шейдеров при экспорте. Для мобилок включать: иначе первый показ воды/дождя даст фриз на пол-секунды.
