## 1. Мокрые тайлы

### Данные: это уже есть в sim

«Мокрость» тайла — **не** новое состояние, которое надо изобретать на этапе 18. Она полностью выводится из одного числа: **максимума уровня воды за предыдущий цикл**. Всё, что было ниже него, — мокрое, пока не кончится текущий цикл.

Значит sim не надо трогать вообще. Достаточно, чтобы `Tide` (или `RunState`) отдавал `last_high_level: float` в `cycle_started`. Если этого поля нет — это единственная правка sim на этапе 18, и она однострочная. Проверить при выполнении: скорее всего сизигия уже требует хранить плато `HIGH`, и число там есть.

⚠️ Отметить в отчёте этапа как отклонение, если пришлось добавить поле — по CONVENTIONS правка контракта требует одновременной правки docs/02.

### Реализация: один шейдер на TileMapLayer, а не per-tile

Наивный путь — помечать тайлы альтернативным атласом или менять `modulate` каждой клетки. Это лишний проход по карте 48×45 и лишние данные в сейве.

Правильный путь: **материал на `TileMapLayer` Ground** с двумя uniform'ами:
- `u_wet_world_y` — мировой Y последнего максимума воды (всё ниже — мокрое);
- `u_wet_amount` — 1.0 в начале цикла, линейно к 0.0 к концу («высыхает»).

```gdscript
func _on_cycle_started(_cycle: int) -> void:
	var mark: float = _last_high_level          # из cycle_ended/cycle_started
	_wet_world_y = (TOP_MARK - mark) * PX_PER_MARK
	_wet_mat.set_shader_parameter(&"u_wet_world_y", _wet_world_y)

func _process(_d: float) -> void:
	# amount падает от 1 до 0 за цикл; прогресс цикла берётся из phase_changed
	_wet_mat.set_shader_parameter(&"u_wet_amount", 1.0 - _cycle_progress)
```

### Ключевая техническая деталь: мировой Y во фрагменте

`CANVAS_MATRIX` и `SCREEN_MATRIX` доступны **только в `vertex()`** — во `fragment()` их нет. Это частая ошибка (см. [00](00-godot-4.7-api-facts.md) §2). Мировая координата тянется через `varying`:

```glsl
varying float v_world_y;
varying float v_world_x;

void vertex() {
	vec2 w = (MODEL_MATRIX * vec4(VERTEX, 0.0, 1.0)).xy;
	v_world_x = w.x;
	v_world_y = w.y;
}
```

Так граница «мокрое/сухое» привязана к миру и не зависит от камеры и зума.

### Визуальный рецепт

Три компонента, все в `wet_tiles.gdshader`:
1. **Затемнение** (`u_darken = 0.35`) — мокрый камень темнее.
2. **Сдвиг в холод** — подмешиваем `#1a3a4a` на 35%. Это связывает мокрую зону с палитрой воды и читается как «тут только что было море».
3. **Медленный блик** (`u_sheen = 0.22`) — узкая диагональная полоса по `sin(x*0.06 + y*0.11 - sim_time*0.6)`. Именно она продаёт эффект: статичное затемнение выглядит как грязь, движущийся блик — как вода.

`u_edge_px = 8.0` — мягкая граница в 8 мировых пикселей (четверть тайла). Жёсткая граница по пикселю выглядит как артефакт.

### Побочный эффект, который надо проверить

Тот же материал стоит на всём `TileMapLayer`, включая жилой утёс наверху. При сизигии (`HIGH = +2`) мокрой окажется полоса до отметки +2 — это **правильно и желательно**: игрок видит, куда доходила большая вода. Проверить на приёмке.

## 2. Отражения

Промпт: *«у кромки воды — зеркальная копия ближних спрайтов (альфа 0.2, vertical flip, смещение волной). Только у линии воды, дёшево»*.

### Три подхода и выбор

| | Стоимость | Плюсы | Минусы |
|---|---|---|---|
| **A.** Второй `Camera2D` в SubViewport, `scale.y = -1` | полный второй проход сцены | геометрически честно, отражает то, что за кадром | ×2 draw calls: утёс + все агенты рисуются дважды |
| **B.** Дубли-спрайты `scale.y = -1`, `modulate.a = 0.2` | дёшево, точечно | полный контроль: отражаем только 5 ближних агентов | ручная синхронизация позиции и кадра анимации из GDScript; тайлмап утёса не отразить без дубля тайлмапа |
| **C.** Шейдер зеркалит **тот же бэкбуфер**, что уже скопирован ради рефракции | **≈ бесплатно** | 0 лишних draw calls, 0 лишних нод, автоматически отражает вообще всё | отражается только то, что попало в кадр и нарисовано до воды |

**Выбран C** — реализован прямо в `water.gdshader`, отдельного шейдера не нужно.

Минус C («верхушка утёса за кадром не отразится») для вертикального среза несущественен: `u_reflect_fade_px = 48` гасит отражение через полярусa, то есть видно только узкую полосу у кромки — ровно как в промпте («только у линии воды»).

### Код и обязательная защита

```glsl
float surf_uv_y = surf_y / u_view_size.y;
float roff_x = floor(wave_height(px_x + 37.0, amp) * 0.6 + 0.5);   // «смещение волной»
vec2  ruv = vec2(SCREEN_UV.x + roff_x * texel.x,
                 surf_uv_y - (SCREEN_UV.y - surf_uv_y));            // зеркало вокруг кромки

if (ruv.y > 0.0 && ruv.y < surf_uv_y) {   // ← без этого отражение сэмплит само себя
	refl  = textureLod(screen_tex, clamp(ruv, vec2(0.0), vec2(1.0) - texel), 0.0).rgb;
	rmask = 1.0 - clamp(depth / u_reflect_fade_px, 0.0, 1.0);
}
col = mix(col, refl, u_reflect_alpha * rmask);
```

- `+ 37.0` в аргументе `wave_height` — сдвиг фазы: отражение «гуляет» синхронно с волной, но не в такт с рефракцией. Иначе оба эффекта складываются в одно движение и выглядят механически.
- `u_reflect_alpha = 0.20` — ровно из промпта.
- `ruv.y < surf_uv_y` — **обязательно**. Без этой проверки отражение рекурсивно сэмплит уже нарисованную воду и даёт полосатый артефакт, который очень трудно диагностировать.

### Опция «сплющенное отражение»

Если захочется визуально «прижать» отражение к воде:
```glsl
uniform float u_reflect_squash : hint_range(0.3, 1.0) = 1.0;
float mirror_y = surf_uv_y - (SCREEN_UV.y - surf_uv_y) * u_reflect_squash;
```
`< 1.0` сжимает отражение по вертикали. В `water.gdshader` это не заведено — добавить только если на этапе 18 глазами покажется нужным. Лишний uniform без причины — лишняя ручка настройки, которую потом придётся объяснять.

### Когда всё-таки понадобится B

Если появится объект, отражение которого важно, но который выходит за кадр — например **Судно** на 12-м цикле (docs/00 §9, финал забега). Тогда точечно добавить дубль-спрайт по подходу B **поверх** C: они не конфликтуют, C даст общее «мерцание воды», B — конкретное отражение корпуса.

## 3. Приёмка

- [ ] После `HIGH` дно до последнего максимума воды заметно темнее и холоднее сухих тайлов; блик медленно ползёт.
- [ ] К концу цикла мокрость сходит на нет; в следующем цикле граница переехала на новый максимум.
- [ ] Сизигия: мокрая полоса поднялась до +2, видно, куда доходила большая вода.
- [ ] Отражение агента, стоящего у кромки на −1, видно в воде и колышется.
- [ ] Никаких горизонтальных полос в воде (значит защита `ruv.y < surf_uv_y` работает).
- [ ] Отражение гаснет на глубине, а не тянется до дна.
