# 36 — Краш-репортинг и обратная связь от игроков

**Для этапов:** 15 (кнопка «сообщить о проблеме» в меню паузы и настройках), 16 (мобильные сборки), 19 (релизная приёмка), 38 (приватность в титрах).
**Дата ресерча:** 2026-08-21. **Движок:** Godot 4.7.x stable.

**Правило, вокруг которого всё:** после релиза узнать о падении можно **только** тем способом, который заложен в билд заранее. Задним числом не добавляется ничего.

---

## 0. Короткий ответ

| Что | Решение | Цена |
|---|---|---|
| Логи | **встроенное файловое логирование Godot** (`user://logs/`, ротация) — включить и не изобретать своё | 2 строки настроек |
| Бэктрейсы GDScript в релизе | `debug/settings/gdscript/always_track_call_stacks = true` | 1 строка |
| Бэктрейс движка при краше | ⚠️ требует **своей сборки с символами** — для нас неоправданно | — |
| Пакет для баг-репорта | **своя кнопка «сообщить о проблеме»**: версия + сид + цикл + последние события + лог | ~80 строк |
| Sentry | официальный [sentry-godot](https://github.com/getsentry/sentry-godot) существует и живой | ⚠️ зависимость + приватность; **не на релиз, а после** |
| Приватность | без явного согласия — **ничего не отправлять автоматически** | — |

**Главная рекомендация для соло-проекта: не автоматическая телеметрия, а «одна кнопка → файл, который игрок сам пришлёт».** Это покрывает 90% пользы Sentry, не создаёт юридических обязательств и не требует сервера.

## 1. Что Godot 4.7 даёт из коробки

### 1.1 Файловое логирование

Настройки проекта:

| Настройка | Дефолт | Что делает |
|---|---|---|
| `debug/file_logging/enable_file_logging` | выкл. на большинстве платформ | включает запись в файл |
| `debug/file_logging/log_path` | `user://logs/godot.log` | путь |
| `debug/file_logging/max_log_files` | **5** | сколько старых логов хранить; ротация автоматическая |

Логгер ловит `print()`, `printerr()`, `push_error()`, `push_warning()`.

⚠️ **Включить обязательно** — это единственный источник данных, если игрок не пришлёт ничего, кроме «у меня вылетело».
⚠️ **Ротация уже есть** — своей писать не надо.

### 1.2 Бэктрейсы GDScript в релизе (с 4.5)

По умолчанию стек скриптов доступен только в editor/debug. Для релиза:
```
debug/settings/gdscript/always_track_call_stacks = true
```
После этого при ошибке в лог попадает не только сообщение, но и цепочка вызовов. Плюс появляется API:
```gdscript
Engine.capture_script_backtraces()      # ручной снимок стека
```

⚠️ **Известный дефект 4.5:** в release-экспорте номера строк в бэктрейсе GDScript указывают **на сигнатуру функции**, а не на строку ошибки ([godot#106484](https://github.com/godotengine/godot/issues/106484)). Функция определяется верно, строка — нет. ⚠️ **НЕ ПОДТВЕРЖДЕНО**, исправлено ли это в 4.7 — проверить на своём release-билде, намеренно вызвав ошибку.

⚠️ Цена флага — небольшой оверхед на каждый вызов функции. Для нашего бюджета (тик ≤2 мс при нагрузке ~0.1 мс) незаметно, **но замерить график времени тика до и после стоит**.

### 1.3 Свой `Logger` (с 4.5)

Класс `Logger` + `OS.add_logger()` позволяют перехватывать всё, что печатается:
```gdscript
## _log_message() — обычный вывод; _log_error() — ошибки с бэктрейсом.
## Регистрировать в _init() автолоада.
```
⚠️ Док прямо предупреждает: *«this method will be called from threads other than the main thread»* — обработчик обязан быть потокобезопасным. Для нас это значит: **не трогать из логгера ни `Game.world`, ни ноды**, только складывать строки в кольцевой буфер под мьютексом.

Это ровно то, что нужно кнопке «сообщить о проблеме»: последние N строк лога всегда под рукой без чтения файла.

### 1.4 Бэктрейс краша самого движка

Док про логирование: *«Crash backtraces require debugging symbols in the binary. Official binaries don't provide debugging symbols, so this requires a custom build to work.»*

**Вывод для нас:** нативный краш (segfault в движке или драйвере) читаемого стека не даст. Это дополнительный аргумент **не собирать кастомный шаблон** (research/26 §5) — а если всё же соберём, `debug_symbols=no` уберёт и эту возможность тоже.

⚠️ На Android с 4.5+ можно включать **нативные debug-символы** в пресете экспорта — это делает Play Console crash reports читаемыми. Для мобильной ветки (research/33 §4) включить обязательно.

## 2. Кнопка «сообщить о проблеме»

### 2.1 Что в неё класть

Порядок — от самого полезного к наименее:

| Поле | Откуда | Зачем |
|---|---|---|
| Версия игры и коммит | `ProjectSettings.get_setting("application/config/version")` | без неё репорт бесполезен |
| Версия движка | `Engine.get_version_info()` | |
| **Сид забега** | `Game.world.rng.seed_value` | **воспроизводимость** |
| **Тик / цикл / фаза** | `world.clock` | где именно |
| Число живых агентов, построек | агрегаты | состояние в двух числах |
| Политики | `world.policies.to_dict()` | как игрок играл |
| Последние 30 событий `Events` | кольцевой буфер (уже есть в дебаг-панели) | что происходило перед проблемой |
| Последние 100 строк лога | свой `Logger` (§1.3) | ошибки движка |
| ОС, ЦП, ГПУ, разрешение | `OS.get_name()`, `OS.get_processor_name()`, `RenderingServer.get_video_adapter_name()`, `DisplayServer.window_get_size()` | железо |
| Локаль, масштаб UI | `Settings` | вёрстка |
| **Журнал команд** | `SimWorld.command_log` | ⚠️ **самое ценное**: сид + журнал = полное воспроизведение забега (research/25 §2.1) |
| Текст от игрока | поле ввода | «что вы делали» |

⚠️ **Чего НЕ класть:** имя пользователя ОС, путь к домашней папке (`user://` в globalize виде содержит логин!), IP, содержимое буфера обмена, список процессов. См. §4.

### 2.2 Как отдать игроку

Три способа, по возрастанию удобства для нас и убыванию — для игрока:

| Способ | Как | Плюс | Минус |
|---|---|---|---|
| **Файл** | записать `user://reports/report_<tick>.json`, открыть папку через `OS.shell_open(ProjectSettings.globalize_path("user://reports"))` | работает везде, ничего не отправляет | игрок должен приложить файл |
| **Буфер обмена** | `DisplayServer.clipboard_set(text)` | одна кнопка, вставил в Discord | длинный текст не влезет; журнал команд не поместится |
| **Ссылка на форму** | `OS.shell_open("https://forms.../?v=1.0.3")` | привычно | данные придётся вставлять руками |

**Рекомендация: файл + буфер обмена одновременно.** Кнопка пишет полный JSON в папку, **открывает её**, и кладёт в буфер короткую сводку (версия, сид, цикл, последняя ошибка). Игрок вставляет сводку в Discord, а файл прикладывает, если попросят.

⚠️ **`OS.shell_open` на мобилках папку не откроет.** Там — только буфер обмена и «поделиться». Для мобильной сборки ветка отдельная.

Готовый черновик — [`code/crash_report.gd`](code/crash_report.gd).

### 2.3 Куда поставить кнопку

- **Меню паузы** — основное место (игрок уже остановился, потому что что-то не так).
- **Экран настроек** — рядом с версией игры.
- ⚠️ **Не в главное меню на видном месте** — это сигнал «игра падает».
- ⚠️ **Автоматически после краша показать нельзя:** после падения процесса игра уже не работает. Можно проверить при следующем запуске: если в `user://logs/` есть лог с необработанной ошибкой и он новее последнего репорта — предложить отправить.

## 3. Sentry и аналоги: стоит ли

**Официальный SDK существует и живой:** [getsentry/sentry-godot](https://github.com/getsentry/sentry-godot) — C++ GDExtension поверх `sentry-native`, стабильная версия 1.x, поддержка Godot 4.5+, автоматические краши на Windows/macOS/Linux плюс перехват ошибок GDScript и шейдеров.

### За

- ловит **нативные** краши (segfault движка/драйвера) — то, чего наш собственный механизм не увидит в принципе;
- агрегация: «эта ошибка у 40 игроков» вместо трёх писем;
- ⚠️ особенно ценно для **мобильной** ветки, где краш-рейт Godot-игр без работы над ним ~4% (research/33 §1).

### Против

- **зависимость GDExtension** → пересборка/проверка при каждом обновлении движка, конфликт с кастомным шаблоном экспорта;
- **приватность**: автоматическая отправка данных требует согласия и упоминания в политике приватности (§4, [38](38-legal-minimum.md));
- **бесплатный тариф ограничен** по объёму событий; при всплеске один баг съедает квоту;
- для соло-проекта на 20 бета-тестеров ценность близка к нулю: проще спросить.

### Вердикт

**Не ставить к первому релизу на Steam/itch.** Заложить вместо этого §2 (кнопка + файл) — она даёт воспроизводимость, которой у Sentry нет (там нет нашего сида и журнала команд).

**Пересмотреть при выходе на мобилки**: там нативные краши — главный источник проблем, а спросить игрока невозможно.

⚠️ Если решите ставить — **включать только с явного согласия при первом запуске**, а не по умолчанию.

## 4. Приватность: что можно и чего нельзя

### 4.1 Общее правило

**Ничего не отправляется автоматически без явного согласия.** Всё, что игрок отправляет сам, нажав кнопку, — это его действие, и оно юридически проще.

### 4.2 Что нельзя собирать без согласия

- любые **идентификаторы устройства** (MAC, IDFA/AAID, серийники);
- **имя пользователя ОС** — ⚠️ оно утекает через `ProjectSettings.globalize_path("user://")`, если положить путь в репорт. **Обрезать до `user://`** или заменять домашнюю папку на `~`;
- IP-адрес (собирается сервером автоматически — ещё одна причина не иметь сервера);
- содержимое буфера обмена, список процессов, файловую систему за пределами `user://`.

### 4.3 Что можно всегда

- версия игры и движка, ОС, модель ГПУ, разрешение — техническая информация без привязки к личности;
- **состояние собственного забега** (сид, цикл, политики) — это данные игры, а не игрока.

### 4.4 Требования площадок

| Площадка | Что требует |
|---|---|
| **Steam** | ⚠️ Если игра собирает данные — указать в анкете при публикации. Наш случай («ничего не собираем автоматически») это упрощает |
| **Google Play** | **Data Safety form обязательна всегда**, даже если данные не собираются; политика приватности **нужна всегда** |
| **App Store** | privacy nutrition labels + URL политики приватности **обязательны для каждого приложения** |

Подробности и формулировки — [38-legal-minimum.md](38-legal-minimum.md).

⚠️ **Практический вывод:** отсутствие автоматической телеметрии — не только техническое, но и юридическое упрощение. Оно позволяет в анкетах честно ставить «данные не собираются», что снимает целый класс вопросов при модерации.

| Этап | Действие | Строк |

| **сейчас** | `application/config/version` — без версии все репорты бесполезны | 1 |

| **после релиза на мобилках** | пересмотреть Sentry | — |

## 6. Чек-лист

- [ ] Файловое логирование включено; `user://logs/` появляется после первого запуска; ротация работает (5 файлов).
- [ ] `application/config/version` заполнена и попадает в репорт.
- [ ] `always_track_call_stacks` включён; проверено на **release-экспорте**, что бэктрейс появляется (и известно, врут ли номера строк — [godot#106484](https://github.com/godotengine/godot/issues/106484)).
- [ ] Кнопка репорта: пишет файл, открывает папку, кладёт сводку в буфер.
- [ ] В репорте есть сид, тик, цикл, политики, последние 30 событий, последние 100 строк лога, железо.
- [ ] В репорте **нет** абсолютных путей с именем пользователя.
- [ ] Ничего не отправляется по сети без явного действия игрока.
- [ ] На мобильной сборке кнопка использует буфер обмена, а не `shell_open`.
- [ ] Android-пресет собирается с нативными debug-символами.
- [ ] При следующем запуске после падения игра предлагает отправить репорт (по свежему логу).
