# 05 — Время в шейдерах и пауза

Это самый недооценённый пункт этапа 18. Приёмка промпта: *«на паузе шейдер останавливается (TIME → свой uniform от sim‑тика!)»*. Если проигнорировать — на тактической паузе (главная фича управления, docs/01 §2) вода продолжает волноваться, и пауза перестаёт читаться как пауза.

## 1. Факт: TIME на паузе не останавливается

Дословно из документации Godot 4.7:

> *«Global time since the engine has started, in seconds… **It's affected by `time_scale` but not by pausing.** If you need a `TIME` variable that is not affected by time scale, add your own global shader uniform and update it each frame.»*

- `get_tree().paused = true` → TIME идёт.
- `process_mode` узла → не влияет.
- `Engine.time_scale = 0.0` → заморозит, но **это запрещено проектом**: docs/01 §6 и docs/02 §4 прямо говорят, что `Engine.time_scale` не используется, скорость только числом тиков за кадр.
- Официального переключателя нет (issue #27127 висит с 2019).

**Вывод: `TIME` в шейдерах TIDEBOUND запрещён. Внести в `prompts/CONVENTIONS.md` в список жёстких правил кода.**

## 2. Решение: global shader uniform `sim_time`

Это ровно тот путь, который советует документация.

**Шаг 1.** Project Settings → Shader Globals → добавить:
```
sim_time : float = 0.0
```
В `project.godot` это выглядит так:
```ini
[shader_globals]
sim_time={"type":"float","value":0.0}
```

**Шаг 2.** В шейдере — ключевое слово `global`:
```glsl
shader_type canvas_item;
global uniform float sim_time;
```
Работает во всех типах шейдеров (`canvas_item`, `spatial`, `particles`, `sky`, `fog`). Материал ничего не знает про это значение — оно ставится один раз на весь рендер.

**Шаг 3.** Пишет `Game` (он уже владеет тиком и аккумулятором) — см. [`code/shader_time.gd`](code/shader_time.gd):
```gdscript
func sim_seconds() -> float:
	return float(world.tick_count) / float(TICKS_PER_SEC) + _accum

func _push_shader_time() -> void:
	RenderingServer.global_shader_parameter_set(&"sim_time", sim_seconds())
```

## 3. Почему `tick / 10.0 + _accum`, а не просто `tick / 10.0`

Симуляция тикает 10 Гц, экран рисует 60 Гц. Голое `tick/10.0` даёт шаг времени 100 мс — волна поехала бы рывками 10 раз в секунду. Дробная часть `_accum` (аккумулятор, который уже есть в `game.gd` по docs/02 §4) достраивает время до непрерывного.

Свойства этой формулы, все нужные:

| Ситуация | Поведение `sim_time` | Почему правильно |
|---|---|---|
| Пауза (`speed == 0`) | стоит намертво | `_accum` не растёт, тики не идут |
| Скорость ×2 / ×3 | идёт в 2/3 раза быстрее | вода волнуется быстрее вместе с игрой — читается как ускорение |
| 30 fps вместо 60 | тот же ход времени | привязка к симуляции, а не к кадрам |
| Загрузка сейва | продолжается с сохранённого тика | детерминизм визуала «бесплатно» |
| Открыта панель с автопаузой | стоит | автопауза = `speed = 0` |

Побочный приятный эффект: скриншот‑тест этапа 18 («кадр LOW с огнями, кадр HIGH со штормом») воспроизводим — одна и та же фаза одного сида даёт одну и ту же фазу волны.

## 4. Точность float

Забег = 12 циклов × 300 с = **3600 с максимум**. float32 на 3600.0 держит шаг ~0.00024 с — для `sin()` достаточно, обёртка не нужна.

Если появятся забеги 16/20 циклов (docs/00 §17, Release) → 6000 с, всё ещё нормально, но на всякий случай можно завернуть: `fmod(sim_seconds(), 3600.0)`. Ценой одного незаметного скачка фазы раз в час.

## 5. Что НЕ надо привязывать к sim_time

- **UI‑анимации** (пульсация RecallButton на SIGNAL, твины панелей). Они живут по реальному времени и должны работать на паузе — docs/01 §2: «на паузе доступно ВСЁ управление». Для UI — обычный `create_tween()`, `process_mode = PROCESS_MODE_ALWAYS`.
- **Индикатор long‑press** у пальца (этап 12, InputService) — реальное время.
- **Затухание тостов** — реальное время.

Граница простая: **всё, что нарисовано внутри WorldViewport, идёт по `sim_time`; всё, что на UI‑слоях, — по реальному.**

Исключение: `storm_overlay.gdshader` живёт на UI‑слое, но это **погода мира**, а не UI. Он читает `sim_time`. Зафиксировать комментарием в шейдере (уже сделано).

## 6. Частицы и пауза

`GPUParticles2D` анимируются движком, не шейдером — `sim_time` их не остановит. Варианты:
1. `process_mode = PROCESS_MODE_PAUSABLE` (дефолт `INHERIT`) + `get_tree().paused` — но проект паузу движка не использует, у нас `speed = 0`.
2. **Рекомендация:** `speed_scale` частиц ставится из `Game` тем же кодом, что пушит `sim_time`: `particles.speed_scale = float(speed)` (0 на паузе, 1/2/3 по скорости). Так брызги и дождь честно замирают и ускоряются вместе с миром.

Удобно завести в `game/` крошечный `WorldParticles`‑менеджер, который держит список активных `GPUParticles2D` и раздаёт им `speed_scale`. Детали — [04-weather-particles-vignette.md](04-weather-particles-vignette.md).

## 7. Чек-лист приёмки

- [ ] `grep -rn "TIME" godot/assets/shaders/` — ни одного вхождения встроенного `TIME` (только `sim_time`).
- [ ] Пауза на подъёме воды в `HIGH`: кромка, пена, рябь, дождь, блик мокрых тайлов — всё стоит.
- [ ] Скорость ×3: волна заметно быстрее, чем на ×1.
- [ ] После `load()` сейва волна не «прыгает» относительно сохранённого кадра.
- [ ] Пульсация кнопки отзыва на паузе продолжается (это UI, так и должно быть).
