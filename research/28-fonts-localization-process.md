# 28 — Шрифт и локализация как процесс: кириллица, CJK, псевдолокализация, 7 языков

**Для этапов:** 12 (выбор шрифта — решение принимается СЕЙЧАС), 15 (экраны и смена языка), 19 (прогон локалей), 22 (техника i18n уже описана — здесь про процесс и масштаб).
**Дата ресерча:** 2026-08-21. **Движок:** Godot 4.7.x stable.

**Почему это Группа 1.** Пиксельный шрифт задаёт **сетку всего UI**. Шрифт с родным размером 8 px и шрифт с родным 12 px дают разную высоту строки, разные отступы, разную ширину панелей. Смена шрифта после этапа 15 = переверстка. А CJK в планах релиза означает, что шрифт обязан покрывать латиницу + кириллицу + иероглифы **в одной пиксельной сетке**, иначе китайская версия будет выглядеть как другая игра.

---

## 1. Главная развилка: один шрифт или шрифт + fallback

| Подход | Как | Плюсы | Минусы |
|---|---|---|---|
| **A. Один пан-юникодный пиксель-шрифт** | Ark Pixel / Fusion Pixel 12 px на всё | одна сетка, одна метрика, ноль логики fallback | размер файла; ru/en-игроки тащат CJK |
| **B. Базовый шрифт + CJK-fallback** | `FontFile.fallbacks = [cjk_font]` | базовый билд лёгкий | две метрики → строки разной высоты; риск «тофу» |
| **C. Отдельный шрифт на локаль** | грузить по `TranslationServer.get_locale()` | минимальный вес каждой сборки | смена языка на лету требует пересоздания темы |

**Рекомендация: A на этапе 12, с заделом под C к релизу.**
Причина: **сетка важнее мегабайтов до тех пор, пока мегабайты не начали мешать.** Взяв сразу пан-CJK-шрифт с родным размером 12 px, мы верстаем один раз и навсегда; если к релизу вес станет проблемой (мобилки), подключается C — **и вёрстка не меняется, потому что метрики те же**.

⚠️ Подход B выглядит самым разумным, но на пиксель-арте он худший: у двух разных шрифтов почти наверняка разные `ascent`/`descent`, и строка «Цикл 7/12 · 潮汐» получит другую высоту, чем «Цикл 7/12». В обычном UI это незаметно, в пиксельном — разъезжается на пиксель и видно сразу.

## 2. Кандидаты: пиксельные шрифты с кириллицей и CJK

| Шрифт | Размеры | Покрытие | Лицензия | Комментарий |
|---|---|---|---|---|
| **Ark Pixel Font** (方舟像素字体, TakWolf) | **10 / 12 / 16 px**, моно и пропорц. | пан-CJK (zh_cn/hk/tw/tr, ja, ko) + латиница; ⚠️ кириллицу проверить по charmap | **OFL 1.1** (шрифты), MIT (билд-скрипты) | **основной кандидат.** Прямо позиционируется как «out-of-the-box для геймдева» |
| **Fusion Pixel Font** (TakWolf) | 8 / 10 / 12 px | шире Ark за счёт слияния источников | OFL 1.1 | запасной вариант, если у Ark не хватит глифов |
| **Zpix** (最像素) | 12 px | CJK + латиница | OFL | популярен, но проверить кириллицу |
| **GNU Unifont** | 16 px | практически весь Unicode | OFL 1.1 (совр. версии) | ⚠️ «универсальный», но стилистически чужой; как аварийный fallback годится |
| monogram / Public Pixel | 8–16 px | латиница + кириллица | CC0 / OFL | ⚠️ **CJK нет** — путь в тупик, если ZH-Hans в планах |

⚠️ **Ключевое ограничение Ark Pixel, названное самим автором:** *«该字体目前处于积极开发阶段，仍然缺少大量汉字»* — шрифт в активной разработке и **не хватает значительной части иероглифов**. Для UI-текста игры (несколько сотен уникальных знаков) этого почти наверняка достаточно, но **проверять надо не «на глаз», а скриптом** (§4.2).

⚠️ **Про промпт 12.** Он называет monogram, Public Pixel и Press Start 2P. **Press Start 2P кириллицы не содержит вовсе**, monogram и Public Pixel — не содержат CJK. То есть текущая рекомендация промпта ведёт в тупик, если ZH-Hans остаётся в планах. **Это надо поправить в промпте 12 до его выполнения.**

**Размер и сетка.** Ark Pixel 12 px закрывает и требование Steam Deck Verified (≥9 px при 1280×800, рекомендация 12 — research/27 §4.2). Токены получаются:
```gdscript
const FONT_S: int = 12       # было 8 — см. research/27 §4.2
const FONT_M: int = 12       # основной
const FONT_L: int = 24       # 2× родного: чётное кратное => пиксель целый
const FONT_TITLE: int = 24
```
⚠️ **Только кратные родному размеру.** 12 → 24 → 36. `FONT_L = 18` даст мыло независимо от всех настроек импорта.

## 3. Механика fallback и субсеттинга в Godot

### 3.1 Цепочка fallback
```gdscript
var base: FontFile = load("res://assets/fonts/ark-pixel-12px-proportional-latin.ttf")
var cjk: FontFile = load("res://assets/fonts/ark-pixel-12px-proportional-zh_cn.ttf")
base.fallbacks = [cjk]                     # Array[Font]
theme.default_font = base
```
`Font.fallbacks` — массив шрифтов, просматриваемых при отсутствии глифа. ⚠️ **Порядок важен**, и ⚠️ **fallback не выравнивает метрики** — см. §1.

### 3.2 Загрузка шрифта в рантайме (подход C)
```gdscript
func _font_for_locale(locale: String) -> FontFile:
	var path: String = "res://assets/fonts/ark-pixel-12px-%s.ttf" % (
		"zh_cn" if locale.begins_with("zh") else "latin")
	var f := FontFile.new()
	f.load_dynamic_font(path)     # ⚠️ работает и с путями вне res://, если понадобится DLC-пак
	return f
```
⚠️ После смены шрифта тему надо **перегенерировать или обновить**: `theme.default_font = new_font` — этого достаточно, `NOTIFICATION_THEME_CHANGED` разойдётся по дереву сам (research/19 §5).

### 3.3 Субсеттинг: как не тащить 20 МБ

Полный пан-CJK TTF — единицы–десятки мегабайт. Игре нужны **только те знаки, которые реально встречаются в переводах**.

**Пайплайн (вне Godot, один скрипт в `tools/`):**
```bash
# 1) Собрать все уникальные символы из переводов
python3 tools/collect_glyphs.py assets/i18n/*.po > build/charset.txt

# 2) Урезать шрифт по этому набору (fonttools)
pip install fonttools
pyftsubset assets/fonts/ark-pixel-12px-zh_cn.ttf \
  --text-file=build/charset.txt \
  --output-file=assets/fonts/ark-pixel-12px-zh_cn.subset.ttf \
  --layout-features='' --no-hinting --desubroutinize
```
```python
# tools/collect_glyphs.py
import sys, re
chars = set()
for path in sys.argv[1:]:
    for line in open(path, encoding='utf-8'):
        if line.startswith('msgstr') or line.startswith('"'):
            chars.update(line)
# плюс цифры, знаки препинания и всё, что игра собирает в коде
chars.update('0123456789 .,:;!?()[]{}/%+-×·—…«»""')
sys.stdout.write(''.join(sorted(c for c in chars if c.isprintable())))
```
⚠️ **Субсет обязан включать символы, собираемые в коде**, а не только из переводов: цифры счётчиков, `%`, `/`, `×`, названия предметов из `.tres`, имена агентов из пула 40 имён. Забыть — и в бою появятся «тофу»-квадраты там, где subset их не ждал.

⚠️ **Субсеттить только на релизной сборке**, в разработке — полный шрифт. Иначе каждая новая строка перевода требует пересборки шрифта, и кто-нибудь однажды забудет.

⚠️ **Не субсеттить кириллицу и латиницу.** Их полное покрытие — килобайты, а риск «пропал редкий символ» реален (эпитафии, имена).

## 4. Псевдолокализация: встроенная в Godot, включается за минуту

Это **самый дешёвый инструмент против «текст вылезает за панель»** и он в движке уже есть.

**Настройки (Project Settings → Internationalization → Pseudolocalization):**

| Ключ | Что делает |
|---|---|
| `internationalization/pseudolocalization/use_pseudolocalization` | включает режим |
| `…/replace_with_accents` | заменяет символы акцентированными вариантами |
| `…/double_vowels` | удваивает гласные — имитация удлинения |
| `…/expansion_ratio` | добивает строку подчёркиваниями на N% (0.3 = +30%) |
| `…/fake_bidi` | имитация RTL — проверка лейаута |
| `…/override` | заменяет весь текст на `*` — ищет захардкоженные строки |
| `…/prefix`, `…/suffix` | обрамление, чтобы видеть границы строки |
| `…/skip_placeholders` | не трогать `%s`, `%f` |

**Рантайм:** `TranslationServer.pseudolocalization_enabled` (свойство) и `TranslationServer.reload_pseudolocalization()` после правки настроек через `ProjectSettings.set_setting()`.

**Как этим пользоваться на практике:**

1. **`expansion_ratio = 0.3` — рабочий режим.** RU длиннее EN на ~20%, DE — до +35%. Проверяя на +30%, вы закрываете обе.
2. **`override = true` (весь текст в `*`) — разовый прогон** по всем экранам: любая строка, оставшаяся читаемой, — захардкожена. Это ловит то же, что приёмка этапа 19 п.6, но **на пять этапов раньше и за 10 минут**.
3. ⚠️ **Псевдолокализация НЕ ловит текст, собранный в коде** (`"Цикл %d/12" % n`) — он проходит через `tr()` только если ключ переведён. Комбинировать с `override`.
4. **Кнопку «псевдолокаль» — в витрину компонентов** (`_gallery.tscn`, research/19 §8) и в дебаг-панель. Тогда каждый UI-этап проверяется автоматически.

```gdscript
## debug_panel.gd — секция «Локализация»
func _toggle_pseudo(on: bool) -> void:
	ProjectSettings.set_setting("internationalization/pseudolocalization/use_pseudolocalization", on)
	ProjectSettings.set_setting("internationalization/pseudolocalization/expansion_ratio", 0.3)
	TranslationServer.reload_pseudolocalization()
```

### 4.2 Автотест покрытия глифов

```gdscript
# tests/test_fonts.gd — ловит «тофу» до того, как его увидит игрок
static func test_glyph_coverage(t: TestCtx) -> void:
	var font: FontFile = load("res://assets/fonts/main.ttf")
	var missing: Dictionary[String, bool] = {}
	for locale: String in ["ru", "en", "zh_CN"]:
		for text: String in _all_translations(locale):
			for ch: String in text:
				if ch == "\n" or ch == " ":
					continue
				# ⚠️ has_char/get_char_size — проверка наличия глифа
				if not font.has_char(ch.unicode_at(0)):
					missing[ch] = true
	t.check(missing.is_empty(), "нет глифов: %s" % "".join(missing.keys()))
```
⚠️ **Этот тест — единственный надёжный способ проверить утверждение «Ark Pixel покрывает кириллицу».** Написать его на этапе 12 и держать в `run_all.gd` навсегда: он же будет ловить пропажу глифа после каждого субсеттинга.

## 5. CSV или PO на масштабе 7 языков

Техника обоих форматов — в research/22 §3. Здесь — выбор.

| | CSV | gettext PO |
|---|---|---|
| Порог входа | нулевой | нужны `msginit`/`msgmerge` или Poedit |
| Один файл на все локали | да → **конфликты в git при 7 языках** | нет, по файлу на локаль → чистый git |
| Многострочные строки | плохо | хорошо |
| Внешние платформы (Weblate, Transifex, Crowdin) | ограниченно | **нативно** |
| Извлечение строк из проекта | вручную | **встроенный POT-генератор в редакторе** |
| Комментарии переводчику | нет | `# TRANSLATORS:` |
| Исключение строки | нет | `# NO_TRANSLATE` |

Док Godot 4.7 прямо перечисляет плюсы PO: *«gettext is a standard format, which can be edited using any text editor or GUI editors such as Poedit»*, поддержка Transifex/Weblate, *«each locale has its own messages file»*.

**Встроенный POT-генератор** (Project Settings → Localization → POT Generation) распознаёт `tr()`, `tr_n()`, `atr()`, `atr_n()`, свойства `text`/`placeholder_text`/`tooltip_text`, методы `add_item()`/`set_tab_title()`.

### Решение
**Стартовать на CSV (как в промптах), перейти на PO перед первым внешним переводом.**

Обоснование:
- на этапах 00–15 переводы пишем мы сами, двух языков в одном CSV достаточно и это проще;
- ⚠️ **как только появляется третий язык и внешний исполнитель — CSV становится обузой:** один файл, в котором семь колонок правят разные люди, — гарантированные конфликты и потерянные строки;
- **миграция CSV → PO односторонняя и механическая**, делается скриптом за час; обратной дороги не нужно.

⚠️ **Что заложить сейчас, чтобы миграция была дешёвой:**
1. **Только `tr("KEY")`, никогда `tr(переменная)`** — иначе POT-генератор строку не увидит. Уже требуется CONVENTIONS, но проверять грепом.
2. **Ключи — `SCREAMING_SNAKE` с префиксом по домену:** `ITEM_SCRAP`, `HUD_CYCLE`, `HINT_STORM`. Тогда PO-файлы читаются и сортируются осмысленно.
3. **Ни одной строки, собранной конкатенацией.** `tr("HUD_CYCLE").format({"n": n})` — да; `tr("HUD_CYCLE") + " " + str(n)` — нет: в китайском порядок слов другой.
4. **Комментарии-подсказки писать сразу** (`# TRANSLATORS: N — номер текущего цикла`) — при переходе на PO они попадут в файл автоматически.

## 6. Переводчики: где брать и сколько стоит

⚠️ Это не техническая часть, цифры — рыночные ориентиры 2026 из открытых источников, не оффер.

| Канал | Цена за слово | Комментарий |
|---|---|---|
| Фрилансер (ProZ, Upwork, профильные ТГ-каналы) | **$0.06–0.15** | дешевле, но нужен свой контроль качества |
| LSP-агентство (Alconost, Pangea, Transphere и др.) | **$0.10–0.20** | +до 40% к ставке переводчика; берут на себя менеджмент |
| MTPE (машинный + постредактура) | **$0.06–0.12** | ⚠️ для UI игры рискованно: без контекста «Отлив» станет «Low tide» в названии |
| Волонтёры/сообщество (Weblate, Crowdin) | 0 | ⚠️ качество и сроки непредсказуемы; нужен нативный ревьюер |

**Ориентиры по языкам:** ZH-Hans — $0.08–0.18; DE/FR/ES — $0.10–0.15; RU/PT-BR/TR — дешевле; JA/KO — дороже.
**LQA (проверка в билде)** для китайского может **удвоить** стоимость локализации.
**Типовой бюджет:** 20–40 тыс. слов на 5 языков со страницей магазина и базовым LQA — **$6 000–15 000**.

**Что это значит для нас конкретно:**
- Объём текста TIDEBOUND — **малый**: ~13 предметов, 17 построек, 20 черт, 6 карт, 12 разблокировок, HUD, 5 подсказок, экраны. Это порядка **1 500–3 000 слов**, не 20 000.
- То есть **один язык ≈ $150–450**, семь языков ≈ **$1 000–3 000** без LQA. Это не блокирующая сумма — но она есть, и она растёт линейно с каждым добавленным словом.
- ⚠️ **Отсюда практический вывод для этапов 13–15: не разводить текст.** Каждая новая строка — это семь оплаченных строк. Подсказки, тултипы и описания политик писать компактно и **переиспользовать ключи**, где смысл совпадает.

**Порядок языков по отдаче для колони-сима на Steam** (эмпирика, не факт): EN → ZH-Hans → RU → DE → ES-419/ES → PT-BR → FR/JA.

⚠️ **Страницу магазина локализовать отдельно и раньше игры** — она конвертирует вишлисты, а стоит 300–500 слов.

## 7. Что заложить и когда

| Этап | Действие | Почему сейчас |
|---|---|---|
| **12** | Взять **Ark Pixel 12 px** (или Fusion Pixel), а не monogram/Press Start 2P | monogram/PSP не имеют CJK — тупик при ZH-Hans |
| **12** | `FONT_S = FONT_M = 12`, `FONT_L = 24` | сетка UI + Deck Verified ≥9 px |
| **12** | Тест покрытия глифов в `run_all.gd` | единственная проверка «шрифт правда умеет кириллицу» |
| **12** | Кнопка псевдолокали в витрине и дебаг-панели | ловит переполнение до вёрстки, а не после |
| **13–15** | Только `tr("KEY")`, `String.format` с именами, префиксы ключей | делает миграцию на PO механической |
| **13–15** | Экономить количество строк | ×7 за каждую строку |
| **перед 3-м языком** | CSV → PO, POT-генератор, Weblate/Crowdin | CSV на 7 колонок неуправляем |
| **релиз** | субсеттинг CJK-шрифта скриптом | 10–20 МБ → сотни КБ |

## Чек-лист

- [ ] Шрифт покрывает ru + en + zh_CN — подтверждено автотестом, а не «на глаз».
- [ ] Все размеры шрифта кратны родному (12/24/36).
- [ ] Минимальный кегль ≥12 px (Deck Verified).
- [ ] Псевдолокаль `expansion_ratio = 0.3` не ломает ни один экран.
- [ ] Прогон с `override = true`: на экранах не осталось читаемого текста (нет захардкоженных строк).
- [ ] Ни одного `tr(переменная)` и ни одной конкатенации переводов (grep).
- [ ] POT генерируется без ошибок (проверить даже на этапе CSV — это репетиция миграции).
- [ ] Субсет-шрифт содержит все символы всех переводов + символы, собираемые в коде.
- [ ] Смена языка на лету обновляет **все** строки (research/22 §3.2).
