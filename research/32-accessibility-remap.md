# 32 — Доступность и ремап управления: что заложить дёшево сейчас

**Для этапов:** 12 (компоненты и тема), 15 (настройки), 16 (ввод), 19 (приёмка).
**Дата ресерча:** 2026-08-21. **Движок:** Godot 4.7.x stable.

**Почему решения принимаются сейчас.** Доступность почти вся сводится к тому, **как устроены компоненты и палитра**. Добавить экранный ридер к готовому UI — дёшево (Godot делает это сам). Перекрасить игру, в которой смысл передаётся только цветом, — дорого. Ремап, не заложенный в `InputService`, потом требует переписывания всех обработчиков.

---

## 1. Что Godot 4.5+ даёт бесплатно: AccessKit

В **4.5** движок интегрировал [AccessKit](https://accesskit.dev) — кроссплатформенный слой доступности.

**Что получаем без единой строки кода:**
- `Control`-ноды экспонируются в дерево доступности ОС: экранный ридер (NVDA, JAWS, VoiceOver, Orca) читает **подписи кнопок**, значения слайдеров, состояния чекбоксов;
- навигация по меню с ридером работает через штатный фокус;
- доступ к **системным настройкам доступности**: высокая контрастность, «уменьшить анимацию».

⚠️ **Статус — экспериментальный** (формулировка релиз-ноутов 4.5). Поддержка ридера в самом редакторе Godot неполная. Для игры это означает: включаем, проверяем, не строим на этом обещаний.

**Что нужно от нас, чтобы это работало:**

```gdscript
# Каждый интерактивный Control должен иметь осмысленное имя для ридера.
button.tooltip_text = tr("HUD_RECALL_TOOLTIP")   # ридер читает подпись/тултип
# Для нод, у которых нет текста (иконка-кнопка), — явно:
button.accessibility_name = tr("HUD_RECALL")     # ⚠️ свойство появилось в 4.5
```

⚠️ **Три вещи в нашем UI не читаются ридером в принципе и требуют дублирования:**
1. **`TideGauge`** — целиком нарисована в `_draw()` (research/21 §2). Для ридера это пустой прямоугольник. **Лечение: невидимый `Label` рядом с текстовым описанием состояния**, обновляемый раз в секунду: «Фаза: отлив, уровень −6.2, до сигнала 1:20».
2. **`radial_menu`** — тоже `_draw` (research/19 §6). **Лечение: при открытии радиала выставлять `accessibility_name` на сам узел со списком доступных слотов.**
3. **Мир** — агенты, постройки, вода. Здесь честнее не притворяться: игра остаётся визуальной.

⚠️ **Это не «сделать игру для незрячих»** — это уровень «меню и настройки доступны, HUD озвучен». Полная доступность колони-сима — отдельный проект.

**Проверка системных настроек (дёшево и полезно всем):**
```gdscript
# Settings.apply()
if DisplayServer.is_high_contrast_enabled():        # ⚠️ имя уточнить по 4.7 API
	Settings.high_contrast = true
if DisplayServer.is_reduce_animation_enabled():
	Settings.reduce_motion = true
```
⚠️ Точные имена методов в 4.7 **НЕ ПОДТВЕРЖДЕНЫ** — проверить в `DisplayServer` перед использованием. Если методов нет, эквивалент — просто наши собственные переключатели в настройках (§4).

## 2. Цвет: главное, что нельзя чинить потом

### 2.1 Правило, которое надо соблюдать с этапа 12
**Ни одна игровая информация не должна передаваться ТОЛЬКО цветом.**

Инвентаризация нашего UI — где цвет несёт смысл в одиночку:

| Место | Сейчас | Что добавить |
|---|---|---|
| Полосы потребностей агента (`AgentCard`, `AgentChip`) | цвет по порогу | **иконка** состояния (череп/снежинка/капля) + число |
| Точки построек на `TideGauge` | норм/damaged/flooded — цветом | **форма**: круг / круг с крестом / круг с волной |
| Призрак стройки | зелёный/красный | **иконка** ✓/✗ + текст причины (research/17 §2 уже даёт `place_error`) |
| Тосты по важности | цвет | **иконка** слева (уже есть в промпте 12) |
| Rare-карты драфта | рамка-акцент | **подпись** «редкая» |
| Вода / затопление | цвет заливки | форма кромки + анимация — читается и так |

⚠️ **Это не «режим для дальтоников», а базовая читаемость.** Дублирование формой полезно всем: на маленьком экране Deck цвет 16×16-иконки различается хуже, чем силуэт.

### 2.2 Палитра: проверить контраст один раз
Палитра из 32 цветов (research/29 §3) фиксируется на этапе 12/18. **Проверить коэффициент контраста текст/фон** для пар `INK/PAPER`, `INK/PANEL_BG`, `PAPER/PANEL_BG`, `ACCENT/PANEL_BG`:

```gdscript
# tests/test_contrast.gd — WCAG-подобная проверка
static func _relative_luminance(c: Color) -> float:
	var f := func(v: float) -> float:
		return v / 12.92 if v <= 0.03928 else pow((v + 0.055) / 1.055, 2.4)
	return 0.2126 * f.call(c.r) + 0.7152 * f.call(c.g) + 0.0722 * f.call(c.b)

static func contrast(a: Color, b: Color) -> float:
	var la: float = _relative_luminance(a) + 0.05
	var lb: float = _relative_luminance(b) + 0.05
	return maxf(la, lb) / minf(la, lb)

static func test_ui_contrast(t: TestCtx) -> void:
	# 4.5:1 — порог AA для обычного текста; 3:1 — для крупного
	t.check(contrast(Palette.INK, Palette.PAPER) >= 4.5, "INK/PAPER контраст низкий")
	t.check(contrast(Palette.PAPER, Palette.PANEL_BG) >= 4.5, "PAPER/PANEL_BG контраст низкий")
```
⚠️ **Тест, который стоит 20 строк и ловит проблему, которую иначе замечают только в отзывах.** Пиксельный шрифт без сглаживания особенно чувствителен к низкому контрасту.

### 2.3 Режим для дальтоников: как НЕ надо и как надо

**Как не надо:** полноэкранный шейдер-фильтр, симулирующий/корректирующий дальтонизм. Он ломает пиксель-арт (пересчёт цвета даёт значения вне палитры), стоит производительности и решает проблему хуже, чем правильные иконки.

**Как надо:** **альтернативная палитра как данные.** Раз палитра уже генерируется из `.gpl` в `Palette.gd` (research/29 §3.2), сделать вторую:
```
art/tidebound.gpl              # основная
art/tidebound-deuter.gpl       # вариант с разведёнными красным/зелёным
```
и переключатель в настройках, перегенерирующий тему (research/19 §2) — тот же механизм, что смена скина `USE_ATLAS`.

⚠️ **Стоимость: два часа на этапе 18, если заложено в §3.2 research/29. Если не заложено — переписывание всех цветов.** Поэтому решение принимается сейчас, а работа делается позже.

⚠️ **Самый частый тип — дейтераномалия (красно-зелёная).** У нас критичная пара — `DANGER` (красный, «повреждено/опасно») и `SUCCESS` (зелёный, «можно строить»). **Именно её надо развести по светлоте**, а не только по тону: тогда даже без альтернативной палитры разница читается.

## 3. Другое, что стоит дёшево

| Что | Как | Цена |
|---|---|---|
| **Масштаб UI 75–150%** | уже в промпте 15 (`content_scale_factor`) | ✅ бесплатно |
| **Минимальный кегль 12 px** | research/27 §4.2, research/28 §2 | ✅ решение уже принято |
| **Цели касания ≥48 dp** | промпт 16, автотест research/20 §8 | ✅ есть |
| **Тактическая пауза** | ядро игры | ✅ сама по себе мощнейшая фича доступности: игра без реакции на время |
| **Скорость ×1/×2/×3 + пауза** | есть | ✅ |
| **Отключение тряски/вспышек** | флаг `reduce_motion` → `WeatherView` не делает молнию, Tween-пульсации отключаются | ~20 строк на этапе 18 |
| **Отключение хаптики** | уже в промпте 17 | ✅ |
| **Субтитры/лог событий** | тосты уже дублируют звук текстом | ✅ |
| **Долгое нажатие с прогрессом** | промпт 12 | ✅ читается лучше, чем мгновенное срабатывание |

⚠️ **`reduce_motion` стоит завести в `Settings` уже на этапе 15**, даже если он ничего не выключает до этапа 18. Иначе на 18-м придётся править и настройки, и экран настроек, и сейв настроек.

**Что попадает под флаг `reduce_motion`:**
- молния шторма (research/04) — самый очевидный кандидат, вспышки экрана;
- пульсация кнопки отзыва (Tween scale, research/21 §3);
- «подъезд» чисел на экране итогов (research/22 §7);
- покачивание агентов при ходьбе;
- тряска камеры, если появится.

## 4. Ремап управления

Промпт 16 относит ремап к пост-MVP. **Это правильно по объёму работы, но неправильно по архитектуре:** если `InputService` и HUD жёстко завязаны на имена действий, ремап потом потребует правок везде.

### 4.1 Что заложить сейчас (стоит ~0)
1. **Все действия уже в Input Map** (промпт 00) — не читать клавиши напрямую. `Input.is_key_pressed(KEY_B)` в коде = дефект. **Добавить в grep-аудит:**
   ```bash
   grep -rnE 'is_key_pressed|KEY_[A-Z0-9]+' godot/ui/ godot/game/ --include='*.gd'
   ```
   Единственное легальное место — генератор Input Map (research/10 §5).
2. **`physical_keycode`, а не `keycode`** (research/10 §5) — уже решено, и это же основа корректного ремапа на любой раскладке.
3. **Подписи клавиш в UI брать из `InputMap`**, а не хардкодить:
   ```gdscript
   static func action_label(action: StringName) -> String:
       for e: InputEvent in InputMap.action_get_events(action):
           if e is InputEventKey:
               return (e as InputEventKey).as_text_physical_keycode()
       return "?"
   ```
   Тогда подсказка «B — стройка» автоматически станет «N — стройка» после ремапа. **Три строки сейчас против переписывания всех подсказок потом.**

### 4.2 Сам ремап (пост-MVP, но вот как)
```gdscript
## Settings: сохраняем только ОТЛИЧИЯ от дефолта — тогда добавление
## нового действия в новой версии не ломает старый конфиг.
var input_overrides: Dictionary[String, Array] = {}

func apply_input_overrides() -> void:
	for action: String in input_overrides:
		if not InputMap.has_action(action):
			continue                                  # действие исчезло в новой версии
		InputMap.action_erase_events(action)
		for d: Dictionary in input_overrides[action]:
			var e := InputEventKey.new()
			e.physical_keycode = int(d["physical_keycode"])
			InputMap.action_add_event(action, e)
```
⚠️ **Хранить только оверрайды, не полную карту.** Полная карта в конфиге = при добавлении действия в патче игроки получат игру без него.

⚠️ **Захват клавиши в UI** — через `_input` с `set_input_as_handled()`, и обязательно с проверкой конфликтов (одна клавиша на два действия) и кнопкой «сбросить к умолчанию».

⚠️ **Ремап геймпада отдельно от клавиатуры.** На Steam это вообще решается **Steam Input** (research/27 §4.1) — игрок переназначает кнопки в оверлее Steam без нашего кода. **Для Steam-версии свой ремап геймпада не нужен вовсе.** Это сильный аргумент делать сначала только клавиатурный ремап.

## Чек-лист

- [ ] Прогон меню и настроек с включённым экранным ридером ОС: все кнопки называются осмысленно.
- [ ] `TideGauge` имеет текстовое описание для ридера.
- [ ] Ни одного места, где смысл передан только цветом (пройтись по таблице §2.1).
- [ ] Тест контраста зелёный для всех пар текст/фон.
- [ ] `DANGER` и `SUCCESS` различаются по светлоте, а не только по тону.
- [ ] Grep: нет `is_key_pressed`/`KEY_*` вне генератора Input Map.
- [ ] Подсказки клавиш берутся из `InputMap`.
- [ ] `reduce_motion` выключает молнию, пульсации и «подъезд» чисел.
- [ ] Масштаб UI 75/100/150% не ломает лейаут (пересечение с research/22 §8).
- [ ] Игра проходима без звука (тосты дублируют все звуковые события).
