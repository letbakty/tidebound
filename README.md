# TIDEBOUND

Colony sim с рогалайт-структурой. Колония живёт на приливной отмели: океан
уходит и возвращается каждые пять минут и забирает всё, что не успели поднять
наверх. Игрок не раздаёт задачи вручную — он задаёт шесть политик и жмёт одну
кнопку «Отзыв». Забег — двенадцать циклов, около получаса.

Godot 4.7.2, GDScript, пиксель-арт. Разработка идёт, релиза пока нет.

---

## Как запустить

Нужен **Godot 4.7.2** — именно 4.7.x. Версия зафиксирована в `project.godot`
(`config/features`): движок младше откажется открывать проект, движок старше
молча перепишет формат сцен и ресурсов.

**Клонировать, а не скачивать ZIP.** Кнопка «Download ZIP» на GitHub
разворачивается в папку `tidebound-main/`, и стоит ей оказаться рядом с
проектом — движок увидит два комплекта скриптов и откажется собирать оба.
Так уже было дважды, оба раза по 434 ошибки на исправном коде.

```bash
git clone <репозиторий> tidebound
cd tidebound
```

**Проект — это `godot/project.godot`, а не корень репозитория.** В корне лежат
только документы и промпты; открывать надо папку `godot/`.

Дальше — либо из редактора, либо из терминала.

**Из редактора.** Godot → Import → выбрать `godot/project.godot`. Первый запуск
переимпортирует ассеты: около минуты, прогресс-бар внизу. Это нормально и
делается один раз — папка `godot/.godot/` в репозиторий не входит.

**Из терминала.** `godot` ниже — путь к исполняемому файлу движка
(на macOS это `…/Godot.app/Contents/MacOS/Godot`):

```bash
godot --headless --path godot -s res://tools/doctor.gd    # 1
godot --headless --path godot --import --quit             # 2 — дважды,
godot --headless --path godot --import --quit             #     см. ниже
godot --headless --path godot -s res://tools/doctor.gd    # 3 — теперь ноль находок
godot --headless --path godot -s res://tests/run_all.gd   # 4
godot/tools/playtest.sh                                   # 5
```

На Windows shell-скриптов нет, но те же команды лежат рядом батниками:
`godot\tools\doctor.bat`, `run_tests.bat`, `playtest.bat` — их можно запустить
**двойным щелчком**, окно остаётся открытым с отчётом.

Порядок именно такой, и первый шаг не пропускать:

1. **Доктор** — семь проверок окружения. Работает до импорта, потому что
   ключ `-s` выполняет скрипт, ничего не импортируя. Говорит по-русски, что
   не так и что сделать; выход `1`, если есть находки.

   На свежем клоне он и должен найти ровно одну вещь — «кэш импорта
   не собран». Это не поломка, а следующий шаг: папка `godot/.godot/`
   в репозиторий не входит.

   До импорта движок ещё и сам напечатает несколько строк `SCRIPT ERROR`
   про автолоады: без кэша ему неоткуда узнать про глобальные классы. Доктор
   пишет об этом в своём отчёте, а после шага 2 строки исчезают. Ориентир —
   не цвет лога, а последняя строка доктора: «проверок 7, находок 0».
2. **Импорт** — два вызова подряд, и это не опечатка. Обязателен перед первым
   headless-прогоном: без кэша тесты падают на первой же текстуре, и причина
   по сообщению не читается (`docs/02-architecture.md` §7).

   Первый проход печатает около двух десятков ошибок `Failed loading resource`
   на шрифтах, атласе и переводах — это порядок обхода: ресурс успевают
   открыть раньше, чем импортировали его зависимость. Второй проход идёт
   вчистую и стоит секунды. Проще вызвать импорт дважды, чем разбирать
   красный лог.
3. **Доктор ещё раз** — теперь «проверок 7, находок 0» и выход `0`.
   Если что-то осталось, дальше идти незачем: тесты упадут по той же причине,
   только непонятнее.
4. **Тесты** — около пятнадцати тысяч проверок, три минуты. Выход `0` — зелено.
5. **`playtest.sh`** — прогон настоящей игры мышью по экранам. Ловит то, чего
   сьюты не видят: они собирают виджеты поштучно и в дереве игры их нет.

## Куда не надо

- **Не открывать корень репозитория как проект Godot.** Проект — `godot/`.
- **Не распаковывать вторую копию внутрь `godot/`.** Godot сканирует все `.gd`
  под `res://`, и на двух файлах с одинаковым `class_name` валит проект целиком:
  `Class "X" hides a global script class` и сотни ошибок парсера подряд — при
  полностью исправном коде. Так уже было дважды: распакованный с GitHub архив
  `tidebound-main/` внутри папки проекта дал 434 ошибки на ровном месте — сперва
  на `InputService`, потом на `WaterView`.
  Если копия нужна — положите внутрь неё пустой файл `.gdignore`, такую папку
  движок пропускает целиком.
- **Windows: не оставляйте `core.autocrlf=true`.** Установщик Git ставит его по
  умолчанию, и семь shell-скриптов репозитория после клона умирают на первой
  строке (`/usr/bin/env bash^M: bad interpreter`). В репозитории есть
  `.gitattributes` с `eol=lf`, но дерево, склонированное до него, само
  не поправится:

  ```bash
  git config core.autocrlf false
  git add --renormalize .
  git checkout -- .
  ```

  Обратное тоже верно: `.bat` обязаны остаться с CRLF — других концов строки
  `cmd.exe` не понимает. Оба правила прописаны в `.gitattributes`, и доктор
  проверяет обе стороны.

Всё перечисленное проверяет доктор — если сомневаетесь, запустите его.

## Что где лежит

| Папка | Что |
|---|---|
| `godot/` | сам проект. Слои: `sim/` (симуляция без единой ноды) → `game/` и `autoload/` (оркестрация) → `ui/` |
| `docs/` | ТЗ, спека интерфейса, архитектура, экраны, журнал баланса, бэклог |
| `prompts/` | задания этапов 00–20 и ремонтные проходы; `CONVENTIONS.md` — правила кода |
| `research/` | технический ресерч: 48 разборов под конкретные решения |
| `review/`, `audit/` | находки двух волн аудита и статусы ремонта |
| `art-rd/processed/` | отобранные сгенерированные ассеты |
| `design/` | UI-кит артбордами |

Состояние проекта и что делать дальше — **`STATE.md`**, он же первый файл для
любого, кто продолжает работу.

## Чего в репозитории нет

- **`godot/.godot/`** — кэш импорта. Создаётся сам при первом открытии проекта
  или командой `--import --quit`.
- **`vendor/`** — заголовки Steamworks SDK. Лицензия Valve запрещает их
  распространять, поэтому SDK скачивается отдельно с партнёрского портала
  и кладётся в `vendor/steamworks-headers/`. Без него собирается всё, кроме
  Steam-интеграции.
- **`art-rd/`, кроме `processed/`** — сырой вывод генератора вместе с
  отбраковкой. В игру идут только постобработанные файлы.
- **`godot/build/`** и `*.translation` — продукты сборки и импорта.
