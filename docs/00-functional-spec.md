## 1. Паспорт проекта

| Параметр | Значение |
|---|---|
| Жанр | Colony Sim / Management, roguelite-структура забега |
| Движок | Godot 4.7.x (stable) (актуальный stable), GDScript со статической типизацией |
| Вид | 2D side-view (вертикальный срез утёса), pixel art, тайл 32×32 |
| Платформы | Фаза 1: Steam (Windows/macOS/Linux + Steam Deck). Фаза 2: iOS/iPadOS, Android |
| Управление | Мышь+клавиатура, тач, геймпад — один UI-скелет (см. 01-ui-spec) |
| Сессия | Забег 12 циклов ≈ 60–80 минут. Один активный забег + мета-профиль |
| Локализация | RU + EN с первого дня (все строки через ключи), остальные — к релизу |
| Монетизация | Premium, Steam $14.99 |

**Elevator pitch:** колония на приливной отмели. Океан уходит каждые пять минут, открывая дно с руинами, — и возвращается точно по расписанию. Игрок не раздаёт задачи — задаёт правила. Забег — полтора часа, у колонии есть финал.

**Четыре продуктовых правила** (выведены из болей конкурентов, см. ресерч I·03):
1. **Кризис по расписанию, не по кубику.** Всё видно на шкале заранее. Провал = просчёт игрока.
2. **Правила вместо задач.** Ровно одна прямая команда — «Отзыв». Никаких назначений «этот агент → эта задача».
3. **Забег с финалом.** Колония не доживает до равновесия (= скуки). Мета несёт долгую мотивацию.
4. **Тач-версия проектируется первой.** Каждый экран обязан работать пальцем; мышь получает ускорители.

## 2. Словарь терминов

| Термин | Определение |
|---|---|
| **Тик** | Атом времени симуляции. 10 тиков = 1 секунда реального времени при скорости ×1 |
| **Цикл** | Один прилив-отлив: Спад → Низкая вода → Сигнал → Высокая вода. 5:00 минут при ×1 |
| **Фаза** | Одна из 4 частей цикла: `EBB` (Спад), `LOW` (Низкая), `SIGNAL` (Сигнал), `HIGH` (Высокая) |
| **Отметка** | Высота в ярусах относительно нормальной высокой воды. Высокая вода = 0. Жилой утёс: +1..+6. Осушаемое дно: −1..−8 |
| **Ярус** | Горизонтальный уровень мира высотой 3 тайла (площадка + пространство над ней) |
| **Затоплено** | Состояние клетки/постройки/агента: отметка < текущего уровня воды |
| **Сигнал** | Фаза-предупреждение перед подъёмом воды. Звук — колокол |
| **Отзыв** | Единственная прямая команда: все агенты бросают дела и идут вверх к безопасной отметке |
| **Маяк** | Точка сбора, которую ставит игрок; центр притяжения работ на дне |
| **Политика** | Один из 6 ползунков (0..3), управляющих поведением всех агентов |
| **Сизигия** | Усиленный прилив каждый 6-й цикл: вода до +2 вместо 0 |
| **Шторм** | Событие ~каждого 10-го цикла, объявляется за цикл: ломает постройки ниже +3 |
| **Приход** | Существа, приходящие с высокой водой с 4-го цикла |
| **План вылазки** | Карта-модификатор цикла, драфт 1 из 3 на Спаде |
| **Забег** | Одна партия: 12 циклов (MVP), завершается судном / гибелью / досрочным уходом |
| **Журнал** | Мета-профиль: очки за забеги, разблокировки |
| **Реликвия** | Редкий ценный предмет из глубоких руин (−7..−8) |

## 3. Мир и пространство

### 3.1 Геометрия
- Мир — вертикальный срез: сетка тайлов 32×32. Карта утёса №1: **48 тайлов в ширину, 45 в высоту** (15 ярусов × 3 тайла).
- Ярусы имеют отметки **+6 (верх утёса) .. −8 (дальнее дно)**. Отметка 0 — уровень нормальной высокой воды.
- Слева — жилой утёс (отметки +1..+6, узкие площадки), правее и ниже — ступенчатое дно: пляж (−1..−2), отмель (−3..−5), руины затонувшего города (−5..−8).
- Проходимость: агенты ходят по **площадкам** (горизонталь) и **лестницам** (вертикаль). Мир для навигации — **граф узлов** (площадка = узел, лестница = ребро), НЕ тайловый A*. Внутри площадки движение по прямой.
- Карта утёса №1 задаётся вручную в данных (не процедурно). Депозиты расставляются при старте забега сидированным RNG по слотам, прописанным в карте.

### 3.2 Депозиты (источники ресурсов)
| Депозит | Отметки | Ёмкость | Восполнение | Даёт |
|---|---|---|---|---|
| Руины ближние | −2..−4 | 12 ед. | нет | Утиль |
| Руины глубокие | −5..−8 | 20 ед. | нет | Утиль; 15% на −7..−8 — Реликвия (1 на депозит) |
| Отмель (моллюски) | −1..−5 | 8 ед. | +4 за отлив | Сырая добыча |
| Поле водорослей | −2..−5 | 10 ед. | +2 за отлив | Водоросли |
| Плавник | линия −0..+1 | — | 3–6 шт. после каждой Высокой воды | Плавник (сухой) |

Истощение — источник давления: ближние руины кончаются к 4–5 циклу, дальше нужны спуски глубже (лестницы, тросы, дыхательные мешки) и время в пути растёт.

## 4. Время

- **Тик:** 10 тиков/сек при ×1. Вся симуляция — на тиках; секунды ниже — при ×1.
- **Скорости:** ×1 / ×2 / ×3 (масштабируют тики за кадр). **Пауза** — полная (симуляция стоит, UI жив). Автопауза: драфт карт, итог цикла, итог забега, банер кризиса (первое появление каждого типа).
- **Фазы цикла (300 сек = 3000 тиков):**

| Фаза | Длительность | Вода | Что происходит |
|---|---|---|---|
| `EBB` Спад | 45 с | 0 → −8 (линейно-плавно) | Драфт карты (автопауза), установка маяка, агенты спускаются |
| `LOW` Низкая | 150 с | −8 (плато) | Добыча на дне, стройка, расширение |
| `SIGNAL` Сигнал | 30 с | −8 → −6 (медленно) | Колокол. Авто-возврат по политике Осторожность. Ручной Отзыв |
| `HIGH` Высокая | 75 с | −6 → 0 за первые 20 с (стеной), плато 0 | Все наверху. Переработка, отдых, еда. Существа Прихода в воде |

- Конец `HIGH` = конец цикла: **Итог цикла** (автопауза, панель), автосейв, начало следующего Спада.
- Кривая воды между ключевыми точками — сглаженная (smoothstep), уровень — `float` отметка, транслируется в мировую Y.

---

## 5. Вода

- Глобальный скаляр `water_level: float` (в отметках). Обновляется каждый тик по кривой фазы.
- Модификаторы: **сизигия** — плато `HIGH` = +2; карта «Глубокий заход» — плато `LOW` = −10; «Великий отлив» — −12.
- Затопление клетки: `mark(cell) < water_level`. Постройка затоплена, если затоплена её опорная клетка. Агент «в воде», если затоплен его узел.
- Последствия затопления — по таблицам предметов (§7) и построек (§8).
- После ухода воды тайлы, побывавшие под водой, помечаются «мокрыми» на 1 цикл (визуал + сушка плавника на них не идёт).

## 6. Агенты

### 6.1 Базовые параметры
- Старт забега: **6 агентов**. Максимум: 12 (MVP) / 16 (релиз). Пополнение: событие «пришедший по берегу» на Итоге цикла (шанс 25% при Духе колонии > 60, не чаще 1 раза в 2 цикла).
- Имя (из пула 40 имён), **2 черты** из пула 20, одна строка биографии (из пула 30 шаблонов).
- Скорость: **2.0 тайла/с** по площадке, **1.2 тайла/с** по лестнице. Модификаторы черт и потребностей мультипликативны.
- **Котомка: 4 слота** (слот = 1 стак до размера стака предмета).
- Смерть: постоянная. Причины MVP: утопление, шторм (обломки), существо (только если Дух=0 и агент не ушёл — существа не убивают напрямую, см. §9.3). Погибший → запись в Журнале с эпитафией.

### 6.2 FSM состояний
`IDLE → GOTO(target) → WORK(job) / HAUL / GATHER → RETURN (отзыв/авто-возврат) → REST / EAT`; особые: `PANIC` (Дух<30 в воде/рядом существо), `DROWNING`, `DEAD`.
Правило приоритета: `DROWNING` > `RETURN` (отзыв) > `PANIC` > потребности (голод/холод критичные) > работа по скорингу > `IDLE`.

**РЕШЕНИЕ (аудит C2.6): «в воде» для паники = вода у ног**, то есть отметка агента ниже `tide.level + 1` (`Balance.PANIC_WATER_MARGIN_MARKS`). Не «ниже плато прилива»: по плато агент на −2 в разгар отлива, когда вода стоит на −8 и вокруг сухо, паниковал на ровном месте. И не «строго затоплен»: затопленного раньше перехватывает `DROWNING` (см. приоритет выше), и паника от воды стала бы недостижимым кодом. На этом же условии работает выход из паники по Духу ≥ 55.

**Прерывания рвут резервацию.** Отзыв, паника и утопление освобождают взятую задачу (`jobs.release`). Без этого агент оставался с `job_id ≠ −1` навсегда: новую задачу взять не мог, старую не возобновлял, а она вечно числилась занятой.

### 6.3 Потребности (0..100)
| Потребность | Падение | Восстановление | Порог <30 | Порог =0 |
|---|---|---|---|---|
| **Сытость** | −18/цикл | Провизия +60; Сырая добыча +30 (и Дух −5) | скорость −25% | не работает: только ест/лежит (смерти от голода в MVP нет) |
| **Тепло** | −10/цикл; −25/цикл если мокрый | у Очага +30/цикл | скорость −25%, Дух −5/цикл | «болезнь»: скорость −50% до полного отогрева |
| **Дух** | события (см. ниже) | тёплый ужин (+5), Реликвия найдена (+10), новый агент (+5) | паника: игнорирует Жадность, возвращается за 20 с до штатного | отказ спускаться в этом цикле |

События Духа: смерть агента −25 всем; существо в пределах 4 тайлов −10; сырая еда −5; затопление склада −10; шторм пережит без потерь +5.
«Затопление склада −10» считается за КАЖДЫЙ ушедший под воду склад и в момент, когда вода его накрывает (аудит C2.5). До аудита по Духу била только кража существом, а сам потоп проходил молча.
- Флаг **мокрый**: контакт с водой; снимается у Очага за 30 с или сам на границе цикла.
  **РЕШЕНИЕ (ревью SPEC-05/SIM-08):** автоматическая сушка на границе цикла — правило, а не недосмотр. Мокрость — состояние ОДНОГО цикла: агент, ушедший вниз на Отливе, платит за это до конца цикла, но не тащит штраф в следующий. Цена решения известна и принята: очаг как «сушилка для людей» нужен только внутри цикла, а разница −10/−25 к Теплу и черта Мерзляк работают в пределах цикла. Если игре понадобится больше давления, отмена авто-сушки — самый дешёвый рычаг (см. `docs/backlog.md`).
- **Отдых** — скрытая четвёртая шкала: −20/цикл работы, +60/цикл отдыха (`Balance.FATIGUE_PER_CYCLE_MILLI`, `FATIGUE_REST_PER_CYCLE_MILLI`; хранится в тысячных, чтобы не копить float). Влияет только на выбор `REST` в фазе HIGH и игроку как полоса не показывается — полос ровно три.
- **Утопление:** агент в затопленном узле непрерывно 5 с → смерть. Со Снаряжением (дыхмешок) — 20 с. За 2 с до смерти — состояние `DROWNING` (иконка, звук).

### 6.4 Черты (пул 20, эффекты — модификаторы)
| Черта | Эффект | Черта | Эффект |
|---|---|---|---|
| Ныряльщик | утопление 10 с вместо 5 | Боязнь глубины | не спускается ниже −5 |
| Жила | +1 слот котомки | Прожорливый | Сытость −24/цикл |
| Кузнец | скорость Горна ×1.25 | Солевар | Солильня ×1.25 |
| Верхолаз | лестницы 1.6 тайла/с | Неуклюжий | 5% уронить предмет при `RETURN` |
| Стойкий | Тепло −6/цикл | Мерзляк | Тепло −14/цикл |
| Весельчак | +2 Духа/цикл соседям по ярусу | Угрюмый | −2 Духа/цикл соседям |
| Зоркий | шанс Реликвии ×1.5 (его находки) | Пугливый | паника при существе с 8 тайлов |
| Трудяга | все работы ×1.1; Дух −5/цикл без работы | Соня | отдых нужен ×1.5 |
| Ветеран отливов | не паникует никогда | Лёгкий сон | отдых восстанавливается ×1.25 |
| Запасливый | перенос ×1.15 | Бодряк | не нуждается в отдыхе первые 4 цикла |

(Отдых — скрытая четвёртая шкала усталости, влияет только на выбор `REST` в фазе HIGH; не показывается игроку как потребность, чтобы держать «ровно три полосы».)

**РЕШЕНИЕ (аудит C2.7) по трём чертам, которые до аудита были мёртвыми данными:**
- **Неуклюжий** (`drop_chance = 0.05`) — бросок ОДИН на возвращение (переход в `RETURN`), а не каждый тик: посекундная рулетка отнимала бы котомку целиком за один подъём. Уронённое ложится на землю там, где агент стоял.
- **Запасливый** (`carry_mult = 1.15`) — «перенос ×1.15» это скорость С ГРУЗОМ, а не вместимость: вместимость уже занята ключом `bag_slots_add` (Жила), и второй способ «носить больше» в одной таблице был бы несравним с первым.
- **Бодряк** (`no_rest_cycles = 4`) — см. §6.6.

### 6.5 Выбор работы (скоринг)
Каждый свободный агент раз в секунду оценивает доступные задачи:
`score = policy_weight(job.class) × job.base × urgency ÷ (1 + 0.1 × dist_tiles)`
- `policy_weight` — значение соответствующей политики (0..3; 0 = класс запрещён).
- `job.base`: gather 10, haul 10, build 12, repair 12, station_work 10, rest 6, eat 20 (при Сытости<30 — 100).
- `urgency`: 1.0; ремонт повреждённого критичного здания 2.0; переноска портящегося (Сырая добыча) 1.5; груз ниже будущего уровня воды в `SIGNAL` 3.0.
- Ограничение Жадности: цель не дальше N тайлов от ближайшей лестницы (см. §6.6).

### 6.6 Политики (6 ползунков, 0..3)
| Политика | 0 | 1 | 2 | 3 |
|---|---|---|---|---|
| **Жадность** (радиус целей от ближайшей лестницы) | 4 тайла | 8 | 16 | без лимита, включая «не успеть» |
| **Осторожность** (авто-возврат до конца `SIGNAL`) | в момент конца | за 20 с | за 40 с | за 60 с (фактически в начале сигнала) |
| **Ремонт** (вес класса repair) | 0 — запрещён | 1 | 2 | 3 |
| **Стройка** (вес build) | 0 | 1 | 2 | 3 |
| **Заготовка** (вес gather+haul) | 0 | 1 | 2 | 3 |
| **Отдых** (вес rest/eat в HIGH) | 0 | 1 | 2 | 3 |

Дефолт старта: Жадность 1, Осторожность 2, Ремонт 1, Стройка 2, Заготовка 2, Отдых 1.

**Вес класса работ** = значение политики по шкале `[0, 1, 2, 3]` (`Balance.POLICY_WEIGHT`). Ноль — это не «низкий приоритет», а **запрет**: класс отбрасывается до расчёта скоринга.

**РЕШЕНИЕ (ревью SPEC-04):** класс работ `STATION` (работа на станции) управляется политикой **Заготовки** — вместе с `GATHER` и `HAUL`. Седьмого ползунка не будет: производство — это продолжение заготовки, и игрок думает о нём в тех же терминах («сколько сил тратим на припасы»). Соответствие классов и политик целиком: `GATHER/HAUL/STATION → Заготовка`, `BUILD → Стройка`, `REPAIR → Ремонт`, `REST/EAT → Отдых`.

**Числа отдыха и еды (ревью A4 — жили комментарием в коде).**
- Порог «пора»: агент идёт есть при Сытости ниже **55** и ложится отдыхать при Отдыхе ниже **55** (`Balance.EAT_WANT_MILLI`, `REST_WANT_MILLI`). Порог выше «плохо» (30) намеренно: это гистерезис, иначе сытый доедает провизию «на всякий случай», а отдохнувший ложится снова.
- `REST` существует **только в фазе HIGH** и кончается вместе с ней: задача отдыха общая (не резервируется), поэтому прерывает её сам агент на границе фазы. Без этого начатый под конец HIGH отдых тянулся полотлива.
- Коек ещё нет: место отдыха — источник тепла (Очаг). Когда появятся койки, задача переедет на них.
- Черта **Бодряк** (`no_rest_cycles = 4`) отменяет потребность в отдыхе на первые 4 цикла забега — задача `REST` ему просто не подходит.
- Скоринг считается **раз в секунду на агента** (§6.5), а не каждый тик; агенты разнесены по тикам секунды по своему id, чтобы нагрузка была ровной. Задержка выбора до 0.9 с — часть правила, а не дефект.

**Дно потребностей (реализация порогов «=0» из §6.3).**
- Сытость 0: агенту доступны только `EAT` и `REST`, остальные классы отбрасываются до скоринга.
- Дух 0: **латч на цикл** — агент не берёт работу ниже воды этого цикла (`danger_mark`), даже если Дух успел отрасти. Снимается на границе цикла. «Ниже, чем стою» здесь не годится: с таким чтением агент с верхней площадки отказывается и от станции на +3, и от переноски по дому, и колония замирает целиком.
- Тепло 0: флаг **болезни** со скоростью ×0.5 держится до ПОЛНОГО отогрева (не до «тепло ≥ 1»). Считается до расхода тепла в тике — иначе максимум недостижим и вылечиться нельзя даже у очага.

### 6.7 Маяк и Отзыв
- **Маяк** — один на колонию, ставится тапом/кликом по любой клетке дна. Работы в радиусе 12 тайлов от маяка получают бонус ×1.3 к скорингу. Маяк можно переставлять в любой момент.
- **Отзыв** — кнопка/Space: все агенты переходят в `RETURN`, бросив работу (несомое — сохраняют). Повторное нажатие в течение 2 с — «жёсткий отзыв»: бросают и груз (быстрее на 15%).

Исключение — клетки корзин Лебёдки: в этом её смысл.
- Стак на земле подчиняется размеру стака так же, как на складе (аудит R4): долив идёт до предела, остаток ложится отдельным стаком. Иначе «стак 40 утиля» уносится одним слотом котомки.
- Склад под водой не кормит и не принимает груз (аудит R1): затопленный склад не «рекламирует» еду, и разгрузка его не выбирает — иначе голодный ныряет за провизией прямо на Высокой воде.
- **Снаряжение** носимое: выдаётся автоматически агенту с наибольшей Жадностью-полезностью (глубокие работы); +15 с к утоплению, занимает слот котомки.

🔒 = разблокируется метапрогрессией. Правила:
- Стройка: агент с классом build приносит материалы (haul) → строит (5 с на единицу стоимости). Недостроенное затопление переживает без потерь, но материалы «вложены».
- Повреждение (шторм/существа): состояние `DAMAGED` — не работает до ремонта (50% стоимости, класс repair). Материалы ремонта **везут и списывают** так же, как при стройке: задача «починить» объявляется только когда смета лежит в буфере, и списывается по завершении. Ломается только достроенное (`ACTIVE`): в плане ломать нечего, и «починить» его нельзя — недострой остаётся недостроем.
- **Нестроящиеся дефы** (`BuildingDef.buildable = false`): стартовые постройки без сметы — сегодня это Дождесборник. Радиал их не показывает, `place_error` отдаёт `ERR_NOT_BUILDABLE`; стартовая расстановка флаг обходит. Без флага пустая смета давала стройку за один тик из ничего.
- **Кромка площадки** у Лебёдки проверяется буквально: под клеткой корзины (ярусом ниже механизма) обязан быть пол, иначе `ERR_NO_BASKET_SPOT`. Без проверки груз уезжал на клетку, до которой не дойти, а носильщик оставался стоять с резервацией.
- Снос: игрок может снести постройку (возврат 50% материалов, округление вниз).
- Очаг: жжёт 1 сухой плавник/цикл; греет радиус 4 тайла; не заправлен — не греет.
- Фонарь: жжёт 1 сухой плавник/2 цикла; отпугивает существ в радиусе 3 (🔒 усиленный — 5).
- Лебёдка: зона выгрузки — агенты на дне складывают груз в корзину под ней, лебёдка поднимает 1 стак/6 с наверх без участия агента. Первый шаг автоматизации.
- Конденсатор: +2 пресной воды/цикл пассивно. Дождесборник: +1/цикл, +3 в шторм.

## 9. Производство и кризисы

### 9.1 Рецепты
| Станция | Рецепт | Время | Режим |
|---|---|---|---|
| Горн | 2 утиля + 1 сух. плавник → 1 слиток | 20 с | агент у станции |
| Верстак | 2 слитка → 1 деталь | 15 с | агент |
| Испаритель | → 1 соль | за фазу LOW | пассивно, если не затоплен и на солнце (не шторм) |
| Солильня | 1 соль + 2 сырой добычи + 1 пресная вода → 2 провизии | 10 с | агент |
| Сушила | 3 водоросли → 1 волокно; параллельно сушат до 2 мокрых плавников | 1 цикл | пассивно |
| Канатная | 2 волокна → 1 трос | 12 с | агент |
| Канатная | 1 трос + 1 волокно → 1 снаряжение 🔒 | 15 с | агент |

Заказы станциям: игрок НЕ ставит заказы вручную. Станция работает, пока есть входы и место на складах (политика Заготовка регулирует, кто носит). Лимиты продукции: ползунок на панели станции «до N на складах» (дефолт: без лимита) — единственная тонкая настройка, для MVP можно отложить.

### 9.2 Календарь кризисов (забег 12 циклов)
| Цикл | Событие |
|---|---|
| 1–3 | спокойные (обучение через игру) |
| 4 | первый Приход (1 существо) + банер-объяснение |
| 6 | Сизигия (объявлена с 5-го) |
| 7, 10 | Приход (2 существа; 3 на 10-м) |
| 9 | объявление Шторма |
| 10 | **Шторм** (совпадает с Приходом — пик сложности) |
| 12 | Сизигия + прибытие Судна на Высокой воде → Итог забега |

### 9.3 Приход (существа)
- Спавн: с водой в начале `HIGH`, заходят «из моря» на затопленные ярусы. Уходят в конце `HIGH`.
- Поведение: идут к ближайшей цели в затопленной зоне. Цель-склад → крадут 1 случайный стак и уходят к точке спавна. Цель-постройка (не склад) → «грызут»: 1 повреждение каждые 10 с, пока не сломают или не кончится `HIGH`. Никакого рандома в выборе действия — тип цели определяет поведение.
- Контр-игра: **Шлюз** перекрывает рёбра графа (существо не проходит); **Фонарь** — не заходят в радиус; постройки выше воды недосягаемы.
- Агентов не убивают: агент в 4 тайлах — Дух −10, паника у Пугливых. (Смерть от существ — только косвенная: паника → не успел уйти от воды.)

### 9.4 Шторм
- Объявление за цикл (банер + метка на шкале). В шторм: `LOW` короче на 30%, Испаритель не работает, Дождесборник +3 воды, видимость ниже (виньетка дождя).
- В момент пика (начало `HIGH`): все постройки с флагом «ломается штормом» ниже отметки +3 → `DAMAGED`; Сушила срываются в ноль **на любой отметке** (флаг `storm_always`). Стальные лестницы и шлюзы — иммунны.
- **Агенты в пик шторма:** ниже отметки +1 — гибель (`cause="storm"`, обломки); на +1..+2 — выживает, но становится мокрым и Дух −15. Шторм объявлен за цикл и авто-возврат работает — гибель здесь всегда следствие политики Жадность 3 / Осторожность 0.

| `careful` | Осторожно | авто-возврат +30 с раньше; +3 с к времени утопления у всех; скорость добычи −20% |
| `great_ebb` 🔒 | Великий отлив | плато LOW = −12 (ниже дна: нижний ярус открыт **дольше всего**); LOW +50% времени; следующая Сизигия +1 отметка |
| `calm_water` 🔒 | Тихая вода | Приход этого цикла отменён |

**РЕШЕНИЕ ОКОНЧАТЕЛЬНОЕ (ревью SPEC-03, подтверждено при аудите 22.08): плато ниже −8 не открывает новых клеток, и утёс №1 расширяться не будет.**
Расширение до −10 рассматривалось и отклонено: площадки идут ступенями вправо и на −8 уже упираются в правый край карты (x 38..47 при ширине 48), поэтому ярусы −9 и −10 получились бы узкими тупиками в 6–8 клеток. Ценность глубины поднимается **депозитами** (`EXPANSION-01.md` §1: «Обломки судна» с деталями по 3 очка на −6…−8), а не новой геометрией: идти вниз незачем не из-за нехватки ярусов, а потому что на трёх нижних лежат три одинаковых `ruins_deep`.
 Самая нижняя площадка утёса №1 — отметка −8 (`Balance.BOTTOM_MARK`), депозитов ниже нет. Опуская плато Отлива до −10 или −12, карты `deep_dive` и `great_ebb` дают не глубину, а **время**: вода раньше уходит с нижнего яруса и позже возвращается. Эффект полезный, но называть его «открывает глубокие руины» — обман игрока, и описания карт переписаны честно.

Альтернатива — расширить утёс до −10 (согласованно: `Balance.BOTTOM_MARK`, `CliffDef`, `tools/gen_cliff_01.gd`, депозиты). Это интереснее для реиграбельности и стоит отдельного разговора: см. `docs/backlog.md`.

## 11. Забег и метапрогрессия

### 11.1 Старт забега
6 агентов (случайные имена/черты, сид), 8 провизии, 6 сухого плавника, 4 утиля; стоят: Очаг, Дождесборник, Склад, деревянная лестница до −2. Сид забега показывается (шеринг).

### 11.2 Конец забега
1. **Судно** (цикл 12, на Высокой): все живые агенты «уплывают» + всё со складов, которые в момент прибытия **не затоплены**. Внимание: цикл 12 — Сизигия (вода +2), поэтому склады низких ярусов в этот момент под водой — финальное испытание забега: ценное надо заранее поднять наверх (об этом предупреждает HintCard при объявлении сизигии 11-го цикла).

   **Что именно под водой.** Затопление считается общей формулой проекта `отметка < уровень − ε`, поэтому отметка, равная плато, — это урез воды, и она сухая. При сизигийном плато +2 затоплены отметки **+1 и ниже**, сам +2 — на урезе. Игроку HintCard всё равно советует **≥ +3**: карта «Полная луна» поднимает плато выше +2 (`next_spring_add`), и запас в один ярус — не перестраховка.

   **Момент прибытия — пик Высокой воды:** тик, на котором вода достигает плато фазы HIGH, то есть `tick_in_phase == min(HIGH_RISE_TICKS, длина HIGH)`, считая после подъёма воды в этом тике. Не начало HIGH: там вода ещё на уровне Сигнала (−6), под ней только −7 и −8, и испытание сизигии не срабатывало бы вовсе. Не конец HIGH: «в момент прибытия» — момент, а не диапазон, и растягивать его до границы фазы значило бы отдать снимок на откуп длительности фазы, которую правят шторм и карты. Снимок делается ровно один раз за забег; забег завершается на границе HIGH→Спад, как и раньше.
2. **Гибель всех** → итог с 30% очков.
3. **Досрочный уход** (доступен с 8-го цикла из меню): судно вызывается на следующий цикл, −25% очков.

**Очки** = Σ(очки предметов на складах) + 5×живой агент + 10×реликвия (сверх очков предмета — итого 20). Типичный диапазон: 30–90.

- **Автосейв** на границе цикла (Итог цикла), плюс при выходе из Game. Один слот на забег.
- Формат: JSON-снапшот полного sim-состояния + версия схемы (`save_version: int`) + сид. Мета-профиль (Журнал) — отдельный JSON.
- Загрузка старой версии: миграция или честный отказ с сообщением (в EA допустимо).
- Детерминизм: сид + журнал не требуется (снапшот полный); RNG-состояние сериализуется.

## 15. Аудио (события → звук)

Колокол Сигнала (главный звук игры, 3 удара) · нарастающий шум воды на подъёме · брызги прихода воды · глухой сдвиг при смене фазы · звуки станций (горн, канатная) · стройка · смерть (одиночный низкий колокол + пауза эмбиента 2 с) · существо (скрежет) · шторм (ветер+дождь) · UI (тап/подтверждение/отмена/драфт) · **вертикальный эмбиент-кроссфейд**: чайки+ветер наверху ↔ капель+гул в руинах, по позиции камеры. Музыка: 2 трека (спокойный LOW / тревожный SIGNAL-HIGH), кроссфейд по фазе.

## 16. Лимиты и производительность

- ≤16 агентов, ≤6 существ, ≤400 стаков предметов в мире, ≤8 PointLight2D на экран.
- Тик симуляции ≤ 2 мс на слабом мобильном (бюджет); 60 fps на Steam Deck и iPhone; ≥30 fps на Redmi Note 11.
- Симуляция — фиксированный тик, отделена от рендера (см. 02-architecture). Скорость ×3 = 3 тика за кадр, не ускорение таймеров.
- RNG — только сидированный `SimRNG`; в sim-коде запрещены `randi()`/`randf()` без генератора.

## 17. Definition of Done по этапам

**Vertical Slice (6 недель):** цикл 4 фаз + шкала; 6 агентов (1 потребность — Сытость); политики Жадность+Осторожность; Отзыв+маяк; утиль+сырая добыча; цепочка горн→слитки→лестницы; постройки: лестница дерев., помост, склад, горн; 5 циклов + экран итога; смерть от воды; программерский арт; мышь. **Критерий:** в момент Сигнала возникает напряжение (плейтест 5 человек).

**MVP (4 месяца):** всё из §3–§13 кроме 🔒-контента и утёсов 2–3; 12 агентов; тач-управление полностью; финальный арт утёса №1; свет+шейдер воды; звук; сейвы; RU/EN. **Критерий:** закрытая бета 20 человек, медиана сессии ≥45 мин, ≥50% доигрывают забег до конца.

**Release (8–9 месяцев):** 3 утёса; 16 агентов; полный пул черт/карт/разблокировок; забеги 12/16/20; достижения; 7 языков; Steam Deck Verified.

**Не делается никогда:** мультиплеер, аватар игрока, боёвка с уроном/HP у агентов, процедурные утёсы, моды на релизе, диалоги/квесты.
