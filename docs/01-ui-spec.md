# TIDEBOUND — UI-спецификация

Версия 1.0 · построена на ресерче UI восьми management-игр (RimWorld, ONI, Against the Storm, Stacklands, Kingdom Two Crowns, Dredge, Rusty's Retirement, Fallout Shelter), Godot Theme-системы и стратегий разрешения (август 2026). Правила игры — [00-functional-spec.md](00-functional-spec.md), слои кода — [02-architecture.md](02-architecture.md).

---

## 1. Три несущих решения

### 1.1 Разрешение: гибрид «пиксельный мир + нативный UI»
Принцип Celeste: «стили не перетекают из одного мира в другой» — мир рисуется в низком разрешении, UI — в нативном, и они не смешиваются.

- **Мир:** `SubViewport` с базой **640×360** (официальная рекомендация Godot: целочисленно масштабируется в 720p/1080p/1440p/4K; 320×180 слишком груба для colony sim, 960×540 теряет ступени зума). На SubViewport: `default_texture_filter = Nearest`, `snap_2d_transforms_to_pixel = true`, `snap_2d_vertices_to_pixel = true` (per-viewport, НЕ глобально).
- **UI:** обычные Control-ноды в нативном разрешении окна поверх `SubViewportContainer` (`stretch = true`, целый фактор). Пиксель-шрифты в UI рендерятся в нативной сетке крупным кеглем — чётко, но стилистически едино с миром.
- **Проектный stretch:** `mode = canvas_items`, `aspect = expand` (Steam Deck 1280×800 — мир станет 640×400 вместо чёрных полос по 40px; вытянутые телефоны — шире).
- **Зум мира:** только целые ступени ×2/×3/×4 (реализация — `stretch_shrink` контейнера либо целый zoom камеры); анимация перехода может быть дробной, но «приземляется» на целое.
- **Масштаб UI:** отдельный слайдер в настройках (паттерн Terraria: раздельные Zoom и UI Scale) через `Window.content_scale_factor`. Дефолты: ПК 1080p — мир ×3, UI 100%; Deck — мир ×2, UI 125%; телефон — мир ×2, UI от DPI.
- **Мышь/тач в мир:** `SubViewportContainer` пробрасывает события с пересчётом координат сам; конверсия ЕДИНСТВЕННАЯ на проект и разложена на два звена, которые нельзя путать: точка окна → точка мирового SubViewport (деление на `stretch_shrink`) живёт в `Main._to_viewport`, а вьюпорт ↔ мир — в `game/world.gd`, хелперы `viewport_to_world()/world_to_viewport()`. Всё ходит через них; конвертировать «на месте» запрещено. Имена содержат «viewport», а не «screen», намеренно: пока хелпер назывался `screen_to_world`, умножение вместо деления в первом звене уводило клик на 34 клетки от курсора, и никто не видел подмены.
- **Camera2D:** позиция всегда `round()` в пространстве SubViewport; НЕ включать position smoothing вместе с pixel snap (задокументированный джиттер). Плавность — лерп до цели с округлением результата.
- **Screen-space шейдеры** (вода, виньетка шторма): эффекты, которым нужна нативная чёткость, вешаются на `SubViewportContainer` или UI-слой; внутри SubViewport текстура всего 640×360.

### 1.2 Темизация: один Theme + вариации типов; скин = файл
Требование «легко менять элементы и объекты UI» решается на трёх уровнях:

1. **Токены** — `ui/theme/tokens.gd` (`class_name UITokens`, только const): палитра (см. §4), 4 размера шрифта, шкала отступов (4/8/12/16/24), радиусы, толщины рамок. Токен = единственный источник значений.
2. **Сборщик темы** — `ui/theme/theme_builder.gd`: скрипт (`@tool` или EditorScript), который из токенов + атласа UI генерирует `main_theme.tres`: StyleBox'ы, цвета, шрифты, констансы для всех типов и **type variations**: `PanelDark`, `PanelRaised`, `ButtonPrimary`, `ButtonDanger`, `ButtonGhost`, `LabelTitle`, `LabelSmall`, `LabelNum` (tabular), `PolicySliderStyle`, `CardPanel`, `TooltipPanel`. Изменение вида = правка токена/атласа + перегенерация, ноль правок в сценах.
3. **Скин** — пара «атлас + tres»: `ui_atlas.png` (все 9-patch панели, кнопки, иконки в одном атласе, нарезка через `StyleBoxTexture.region_rect` + `texture_margin_*`) и сгенерированный Theme. Замена скина в рантайме: `get_tree().root.theme = load("res://ui/theme/skins/<skin>.tres")` — компоненты подхватят через `NOTIFICATION_THEME_CHANGED`.

Правила: в сценах-компонентах НИКОГДА не задавать цвета/шрифты локально (только theme items и variations через `theme_type_variation`); поверх `CanvasLayer` каскад темы рвётся — корню каждого слоя тема назначается явно; главная тема прописана в Project Settings → GUI → Theme → Custom.

### 1.3 Компонентная библиотека: сцена = компонент, данные через setup()
Каждый элемент — отдельная сцена в `ui/components/` без игровой логики: наружу только сигналы, внутрь только `setup(data)`. Компоненты не знают о sim; панели собираются из компонентов и общаются с игрой строго через `Game.cmd_*` / `Events` (см. 02-architecture §3).

Базовый набор: `PixelButton` · `PixelPanel` (9-patch + заголовок + кнопка закрытия) · `ResourceChip` (иконка + число + **иконка тренда ▲▼** — паттерн Against the Storm) · `PolicySlider` (0–3, крупные ступени) · `AgentChip` (мини-портрет 24×24 + полоска состояния) · `CardView` (карта Плана) · `RadialMenu` (своя реализация: 6 слотов, tap+swipe одним жестом; готовые ассеты из Asset Library писаны под 4.3 и не проверены на 4.7) · `TooltipView` (через `_make_custom_tooltip`, на таче — long-press) · `Toast` · `BannerView` · `ConfirmDialog`.

## 2. HUD: три постоянные зоны и ни одной больше

Ресерч-обоснование: Against the Storm сами переделали «красивый, но нечитаемый» UI на тёмные подложки и минимум декора; главные жалобы жанра — перегруз экрана и мелкие немасштабируемые списки.

```
┌─[TopBar]──────────────────────────────────────────────┐
│ ⏸ ×1×2×3 [Политики] | Цикл 4/12 | 🍞12▼ 💧8▲ 🪵6 | [Чипы]│
├─┬─────────────────────────────────────────────────────┤
│T│                                                     │
│i│                МИР (SubViewport)                    │
│d│                                                     │
│e│                                        [EventBanner]│
│G│                                        зона тостов  │
│a│                                                     │
│u│                                     ┌──────────┐    │
│g│                                     │  ОТЗЫВ    │   │
│e│                                     └──────────┘    │
└─┴─────────────────────────────────────────────────────┘
```

1. **TideGauge** (левый край, ~48px нативных): вертикальная шкала прилива. Текущий уровень (стрелка-поплавок), закрашенная зона воды, деления ярусов, метки построек (точки по отметкам), прогноз: мини-иконки следующих 3 циклов (сизигия ⚠, шторм ⛈ — виден с объявления), таймер фазы. Тап по шкале — тултип-легенда. Это «лицо» игры — делается красиво в первую очередь.
2. **TopBar** (верх, одна строка): пауза/скорость (Space; на паузе доступно ВСЁ управление — тактическая пауза Against the Storm; unpause возвращает прежнюю скорость), **кнопка «Политики»**, номер цикла/всего, 4–5 `ResourceChip` (провизия, вода, топливо-сухое, детали) с трендами, ряд `AgentChip` (тап — камера к агенту, второй тап — карточка; паттерн colonist bar RimWorld). При >8 агентов чипы сжимаются до точек-статусов.

   Кнопка политик стоит **здесь**, среди постоянных команд, и подписана словом, а не иконкой. Шесть политик — единственный постоянный рычаг игрока, и до этой кнопки он открывался только клавишей `P` и свайпом от правого края: на экране входа не было вовсе, и игрок, не нашедший панель, смотрел на скринсейвер. Не в правый низ: там мёртвая зона «Отзыва».
3. **RecallButton** (правый низ, ≥64px): единственная командная кнопка. Состояния: обычная / пульсирует на SIGNAL / «жёсткий отзыв» при повторном нажатии 2 с. Зона вокруг неё — «мёртвая» для тостов (антипаттерн Fallout Shelter: попап поверх кнопки Rush).

**Тосты/алерты** — правый край выше кнопки отзыва, группируются по типу («3 стака утиля унесло водой» — одна карточка ×3, не три), важность цветом, тап — камера к месту события, свайп — скрыть. Персистентные только критические, и каждый снимается своим событием, а не таймером: «агент тонет» — до Отзыва, «колония на грани» (живых ровно `WIPE_THRESHOLD`, docs/00 §11.2) — до конца цикла или до прихода человека.

**Оверлеи мира** (паттерн ONI, вместо постоянных индикаторов): тумблеры в радиале по долгому нажатию на пустом месте либо клавиши F2–F4 — «отметки ярусов», «зоны затопления следующего прилива», «кто чем занят» (подсветка занятий — Alt в Against the Storm).

## 3. Панели

Все панели — НЕмодальные листы поверх мира (мир виден и живёт), закрытие свайпом-вниз/Esc/крестиком; одновременно открыта максимум одна (открытие новой закрывает старую). Автопауза только там, где решение (драфт, итоги).

| Панель | Форма ПК | Форма тач | Состав |
|---|---|---|---|
| **PolicyPanel** | правая панель 320px | шторка справа (свайп от края) | 6 `PolicySlider` с подписями значений («Осторожность 2: возврат за 40 с»), подсказка эффекта |
| **AgentCard** | нижняя панель | bottom sheet на полэкрана (свайп вверх — детали) | портрет, имя, 2 черты (тап — тултип), 3 потребности полосами, состояние, котомка 4 слота, кнопка «к агенту» |
| **BuildRadial** | радиал у курсора (удерж. ПКМ/B) | радиал у пальца (long-press по месту) | 6 слотов построек + слот «ещё» (вторая страница при >6 доступных); валидность места подсвечивается сразу; после выбора — призрак постройки с зелёной/красной подсветкой и линиями до ресурсов (паттерн Against the Storm) |

## 4. Палитра и шрифты

- Палитра мира — 32 цвета, две температурные зоны (см. GDD): холод внизу `#1a3a4a→#2d6b7a`, тепло наверху `#c9a15e/#e8c170`. UI — тёмные полупрозрачные подложки `#0e1a20 @ 92%` (читаемость по урокам Against the Storm), текст `#e8eff0`, акцент — янтарь `#e8c170` (кнопки действий), тревога — `#d4553a` (сигнал/опасность), успех — `#7aa85e`. Семантические цвета не совпадают с декоративными.
- Шрифты (кириллица обязательна): **основной текст/цифры — monogram или Public Pixel (CC0, кириллица)**; заголовки — допустим Press Start 2P (OFL, кириллица, широкий — только для коротких заголовков). Настройки FontFile: Antialiasing=None, Hinting=None, Subpixel=Disabled, MSDF=off, Mipmaps=off; кегль — строго целые кратные базового размера шрифта. На 4.5+ проверять, что fixed-size шрифты не попали под per-viewport oversampling (известные регрессии bitmap-шрифтов).
- Числа, которые сравнивают глазами (ресурсы, очки), — моноширинной вариацией `LabelNum`.

## 5. Тач и платформы

- Тач-цели ≥ 48dp (44pt iOS) с зазором ≥8dp. Основной шрифт на телефоне ≥ 17pt физических.
- Safe area: HUD в `MarginContainer` с отступами из `DisplayServer.get_display_safe_area()` + ручной фолбэк-минимум (известные баги на части Android/Windows).
- Жесты мира: 1 палец — панорама; пинч — зум (ступени); тап — выбор; long-press — радиал; long-press по UI — тултип; двойной тап по пустому — скорость; свайп от правого края — политики.
- Ничего не строится на drag-and-drop юнитов (антипаттерн Fallout Shelter: половина перетаскиваний срывается о панораму). Выбор = тап, назначение = не существует (агенты автономны).
- Камера никогда не «похищается» событиями — только тап по тосту ведёт к месту (антипаттерн автозума Fallout Shelter).
- Steam Deck: раскладка геймпада из 00-functional §13; проверка читаемости с вытянутой руки (UI 125%).

## 6. Доступность и мелочи, которые дёшевы сейчас и дороги потом

- Все интерактивные Control — с `focus_mode` и видимой рамкой фокуса (геймпад/клавиатура из коробки).
- Цвет никогда не единственный канал: тренд = стрелка+цвет, опасность = иконка+цвет.
- `FoldableContainer` (4.5+) для сворачиваемых секций настроек/журнала.
- Скорость игры и автопаузы — уважают `Engine.time_scale` НЕ используем: скорость только через количество тиков (см. архитектуру).
- Все строки — `tr()` с первого компонента; ключи в `assets/i18n/strings.csv`.
